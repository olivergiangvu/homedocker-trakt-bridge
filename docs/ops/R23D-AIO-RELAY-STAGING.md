## Scope and security boundaries

1. `scripts/audit-v140-r23d-host-preflight.py` is **READ-ONLY**. It checks running RC6 immutable reference, AIO localhost :3240 port, retained comparator, stopped R23A, current R23B read-only/no-production-mounts/dedicated bridge and localhost health 17041/17141, plus absence of new proposed R23D gateway/relay loopback port reservations. It never logs in, requests AIO watch-state or starts/stops/removes containers. The status `PREFLIGHT_PASS` is **not** a claim that egress is blocked or real AIO normalization works.
2. `scripts/serve-v140-r23d-aio-get-relay.py` is a **temporary opt-in foreground host process, NOT deployed by this work**. It refuses startup until a **separately created and inspected** gateway-only R23D canary exists: `homedocker-v140-r23d-gateway-canary` on its own `homedocker_v140_r23d_local` Docker bridge, read-only rootfs, pinned source SHA-based local image tag, nonroot UID, one minimal private read-only sanitized identity proof file mount, and only port 17145 mapped to host loopback. It obtains the bridge gateway IPv4 and EXACT container IPv4 from Docker inspect. It binds only the bridge gateway IPv4 port 17420 and only accepts that source container IPv4 (not 127.0.0.1 or the public LAN IP). No systemd service is created, no token/user/password file and no direct AIO DB access.
3. GET allowlist: **only** `/jellyfin/Users/Me`, `/jellyfin/Shows/NextUp` with optional `Limit=1..50`, and `/jellyfin/Items/{opaqueSeriesId}` with strict alphanumeric/_/- ID. No `/Users/AuthenticateByName` login, `/UserItems/Resume`, /PlaybackInfo, streaming, images, watch-state POST, Trakt or arbitrary proxy URL. Every GET requires one well-formed `X-Emby-Token` user session; the token remains only in memory, never echoed in status/body/logs. Upstream destination is a **fixed** host-loopback `http://127.0.0.1:3240/jellyfin`, redirects disabled, 2MiB NextUp / 128KiB detail limits, conservative timeouts.
4. The relay is **not** a magic egress firewall. Docker masquerade disabled does **not** prove a container cannot reach other LAN/host destinations. A dedicated bridge and source-IP allowlist reduce the exposed HTTP surface but do not replace audited host firewall rules and network policy. **Do not send a real session token into a running R23D canary until its egress, mount, image, source IP and relay security are separately approved and tested on the actual HomeDocker host.** AIO GET handlers may refresh their own caches even without an explicit write request.
5. Return values from this relay are bounded JSON. AIO GET 401/403/404/429/503 propagate as status with generic JSON, no upstream body. Unknown/malformed paths and any non-GET are rejected before reaching AIO. Failed metadata is fail-open in the Gateway, never silent playback-history deletion. The relay cannot normalize by itself.
