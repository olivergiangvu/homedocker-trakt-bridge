# v0.9.1 performance / freshness RC

v0.9.1 is the pre-1.0 performance hardening candidate. It does not change the database schema or AIOStreams watch-state representation.

## HomeDocker baseline before v0.9.1

Measured on the v0.9.0 source canary:

```text
local image size            163.03 MiB
idle memory                 ~27.14 MiB
idle CPU                    ~0.00-0.02%
transient healthcheck sample 37.65% CPU / 40.91 MiB
Bridge pull cache TTL       900 s
manifest ttlSeconds         900 s
authoritative full pull     ~8553 ms
cached pull                 ~28 ms
```

The application source itself is small; the Node runtime dominated the image footprint.

## v0.9.1 changes

### Image footprint

- production runtime no longer inherits the complete Node Alpine image
- only the Node executable is copied into a minimal Alpine runtime
- the production Node executable is stripped in a build-only stage
- runtime keeps only the TLS/C++ libraries required by Node
- healthcheck uses BusyBox `wget` instead of spawning an additional Node process every 30 seconds
- CI rejects a local runtime image larger than 122 MiB

CI measurement after stripping: approximately `120.25 MiB`, about 26% below the HomeDocker v0.9.0 baseline.

### Sync freshness

The previous single `PULL_TTL_SECONDS` control is split into:

```env
PULL_CACHE_TTL_SECONDS=60
PULL_HINT_SECONDS=60
```

- `PULL_CACHE_TTL_SECONDS`: Bridge-side matching-version cache lifetime
- `PULL_HINT_SECONDS`: `watchState.pull.ttlSeconds` advertised to AIOStreams

Existing deployments that only define `PULL_TTL_SECONDS` remain compatible; it is accepted as the Bridge cache TTL fallback and also becomes the hint when the new variables are absent.

Successful `scrobble:pause` now invalidates the Bridge pull cache. A local AIOStreams playback pause therefore does not wait for the normal cache TTL before the next pull can converge.

## Compatibility

```text
DB schema             1
pull representation   watch-state-v0.3.6
pull cache namespace  pull-state:v5:*
PULL_IDENTITY_MODE    trakt (HomeDocker recommendation)
```

No DB migration or cache purge is required.
