# HomeDocker Trakt Bridge v1.4.0 — Unified Gateway (Stable release notes)

**Status:** **PUBLISHED STABLE** on [GitHub, 2026-10-20](https://github.com/olivergiangvu/homedocker-trakt-bridge/releases/tag/v1.4.0), exact tag commit [`33e97c9`](https://github.com/olivergiangvu/homedocker-trakt-bridge/commit/33e97c9ffc52003f7f9ac11f37b7c092ef993207). The release is distinct from host installation, Gateway listener provisioning and client ingress acceptance. Earlier pre-tag release-HOLD/source-candidate text is preserved in the [qualification record](v1.4.0-release-qualification.md).

## Included in v1.4.0

- **One Trakt writer / one process / one dashboard.** Keep the v1.3 sync engine's bidirectional Trakt ↔ AIOStreams watch-state, scrobble, resume protections and existing profile/SQLite storage. No second Bridge, Gateway DB or Trakt OAuth writer.
- **Integrated read-only Jellyfin NextUp Identity Gateway.** AIOStreams is the primary Jellyfin-compatible source. A provisioned and correctly mapped same-user Gateway can project a *qualified TV-series alias collision* down to one NextUp card, using an existing Bridge-owned verified identity graph. No AIO SQLite, Trakt history, playback, or watched-marker modifications.
- **AUTO ON NextUp filtering once the operator provisions the Gateway listener and an exact source/user/profile mapping.** No manual first-time Turn ON is required. The profile-source-specific **Turn OFF** override is immediate, persistent across restarts, and takes priority. Turn ON clears that operational OFF state. AUTO ON reads do not create media_cache rows.
- **Safety first:** same-user authenticated `/Users/Me`, exact series IMDb lookups, bounded metadata concurrency/body/timeouts, missing/competing resume safeguards, coherent short-page checks and unmodified upstream NextUp response on ambiguity. Invalid/unconfigured scopes fail OFF. Unknown/nonqualified query shapes are passed through unchanged rather than removing unrelated content.
- **One authenticated Unified Dashboard:** shows actual listener, effective filter mode, verified alias counts and anonymous runtime metrics. A listener in ready state or Identity Filter ON is *not* proof that any client uses the Gateway.

## Different layers of activation

1. **Operator provisions listener (not automatic):** `JELLYFIN_GATEWAY_ENABLED=true`, one selected `JELLYFIN_GATEWAY_SOURCE_KIND=aiostreams` (or separately validated alternative), exact upstream Jellyfin API root, mapped user ID and connected Bridge profile. No public Gateway port or second container is created by default; `.env.example` remains Gateway listener OFF.
2. **Identity Filter AUTO ON:** effective only after valid provisioning and only within the Gateway process; a durable manual OFF remains available from the existing authenticated dashboard.
3. **Client ingress (separate):** requests must actually traverse an approved exact NextUp route to see a normalized view. This release does NOT silently rewrite nginx, QuickConnect, Odin/AIOStreams Desktop login base URL, auth, Resume or streams. Never point a whole Jellyfin client directly to NextUp-only Gateway port 7101.

## Known functional limitations — to address in later stable releases

- **Not a universal double-item fix.** Normalization is currently limited to verified *TV-series alias collisions in eligible `GET /Shows/NextUp` responses*. It cannot guarantee deduplication of every potentially duplicated item or every library/client.
- A paginated/full `Limit` response, later page, unknown total, incomplete/mismatched counts, unrecognized selectors, missing identity or conflicting active resumes is returned unchanged. AIO's NextUp offset/pagination limitations are not fixed by this version.
- Movies and `/UserItems/Resume` are not normalized; progress/playback remains owned by AIOStreams/Trakt.
- AIOStreams Desktop's native query includes `userId`, `Limit=24`, `EnableResumable=false`; the RC2 NextUp policy does not qualify this extra parameter shape. Odin request shapes and client ingress need explicit verification. Client-facing correction is therefore **not claimed as proven** by RC2/CI.
- An off-window (beyond source rank 200) episode was demonstrated with a read-only backend shadow proof-of-concept, but global shelf insertion, ordering, count and playback are **not implemented or claimed**.
- Unverified false-negative duplicates are acceptable known limitations; cross-user visibility, unauthorized card removal, Trakt write duplication and history loss are **not** acceptable deferred bugs.

## Publication versus deployment acceptance

1. **GitHub release:** the reviewed `v1.4.0` source/tag was published from `33e97c9`; the stable GHCR digest above is used by the guarded host helper. The historical R23D `V140_STABLE_RELEASE_HOLD` concerned a *different, broader* privileged system-wide gateway research scope and is not the practical v1.4 release contract.
2. **HomeDocker cutover:** separately verify the exact container/image, owner Compose and Gateway overlay, protected SQLite online backup, old RC2 rollback, one Bridge writer, health/readiness and unchanged AIOStreams. The original helper is **RC2-specific**; do not rerun after Stable is already installed.
3. **Gateway provisioning:** the listener is OFF by default in public examples. Exact upstream source/user/profile mapping is an operator action. When valid, Identity Filter AUTO ON can be overridden by persistent manual OFF.
4. **Client ingress:** no host nginx, QuickConnect, Odin/Desktop login-base or entire Jellyfin API route is auto-changed. Qualified `GET /Shows/NextUp` traffic must be confirmed separately; a listening socket is not evidence of a client fix.
5. **Deferred work:** unsupported NextUp request shapes, full/later pagination and off-window shelf insertion remain out of scope. Do not reinterpret proof-of-concept research as a released fix.

For current host checks and rollback boundaries, see [v1.4 Stable operator guide](../STABLE-V1.4-OPERATIONS.md).

**Rollback:** use the preserved checksum-verified RC2 local image and old Compose image declaration; revert only the Bridge container. Never run two Bridge processes with the same /app/data or OAuth credentials. Restore SQLite only if strictly needed after a controlled decision, not as part of routine rollback.

**Out of scope:** RC3 pagination research PR #140/#141, R5 off-window PR #142, CrossWatch reconciliation, metadata-provider cleanup, AIO Live TV, and additional experimental R23D system-wide guards.
