# v1.3.0-rc.3

This canary extends the AIO false-`unplayed` guard to a second reproduced Jellyfin UserData echo shape without changing compare-only recovery behavior.

## What changed

- Keeps the RC2 positive-resume guard unchanged.
- Adds a second, source-semantic discriminator for zero-position echoes:
  - exact single-item AIO `unplayed`
  - `played=false`, `positionMs=0`, valid duration
  - exact configured HomeDocker sink and delivery identity
  - current local row is `played=0`, `position_ms=0`
  - both `updated_at` and `last_played_at` are stamped inside the same tight transaction window
- Explicit Mark Unwatched remains fail-open because AIO's explicit `unplayed` write does not update `last_played_at`.
- Bulk marks remain outside the guard.
- AIO SQLite remains read-only.
- No DB migration and no Phase B writeback.

## HomeDocker evidence

Playback-generated echo:
- AIO `unplayed` created at 12:52:20.893.
- Local row immediately became `position_ms=0, played=0`.
- `updated_at=12:52:20.910`.
- `last_played_at=12:52:20.910`.
- Positive pause/start/stop followed shortly afterward.

Controlled explicit Mark Unwatched:
- local row changed to `position_ms=0, played=0` at 12:55:03.120.
- `last_played_at` remained at the earlier 12:54:51.678 value.

AIO source behavior matches the capture:
- explicit `unplayed` clears played/position and does not set `lastPlayedAt`;
- a `stop` write always stamps `lastPlayedAt`, including a zero-position stop.

## Canary configuration

```env
AIO_RECONCILER_MODE=compare
AIO_UNPLAYED_ECHO_GUARD=true
```

The public default remains `AIO_UNPLAYED_ECHO_GUARD=false`.
