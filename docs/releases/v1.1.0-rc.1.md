# v1.1.0-rc.1 — Duplicate-history canary

Status: **release candidate / HomeDocker canary only**.

`v1.0.0` remains the stable production release until this candidate passes the acceptance gate below.

## Why this candidate exists

Issue #40 isolated duplicate Trakt history inside the AIOStreams → Bridge write lane even when event-ID idempotency was working.

Two Bridge-visible paths can represent one viewing:

1. a completed AIOStreams `stop` reaches Trakt `/scrobble/stop`; when Trakt returns `action=scrobble`, Trakt has already created the history entry;
2. AIOStreams can then emit a separate `played` mark, or another same-state `played` mark with a different event ID, which v1.0.0 would send to `/sync/history` again.

## What changes

- Adds restart-safe semantic history markers keyed by the resolved canonical Trakt movie/episode ID.
- A successful stop is remembered as `played` only when Trakt itself responds with `action=scrobble`.
- Equivalent `played` or `unplayed` writes for the same canonical item are suppressed inside:
  ```env
  HISTORY_DEDUPE_SECONDS=300
  ```
- Repeated AIOStreams event IDs are still handled by the existing processed-event idempotency layer; this new guard handles different event IDs that mean the same final state.
- Dedupe state uses the existing SQLite cache, so a Bridge restart inside the window does not reopen the duplicate path.

## Safety boundaries

The guard intentionally does **not** collapse:

- `played -> unplayed -> played`;
- a same-state event outside the configured window;
- another movie/episode;
- a stop that Trakt reports as `action=pause`.

No DB schema migration, pull-state representation change, identity-mode change or pull-cache namespace change is required.

This guard can only attribute the Bridge write lane. A native Trakt writer such as Strand remains outside Bridge visibility.

## HomeDocker canary acceptance

Before cutover, back up `bridge.db`, `.env`, Compose and nginx configuration and record the exact v1.0.0 rollback digest.

Run the RC by immutable digest and explicitly keep:

```env
PULL_IDENTITY_MODE=trakt
HISTORY_DEDUPE_SECONDS=300
```

Acceptance requires:

- `/health` reports `1.1.0-rc.1`;
- `/readiness` is ready with DB schema `1` and the existing connected profile;
- one controlled normal viewing produces exactly one new Trakt history play;
- if `scrobble:stop` is followed by an AIOStreams `played` event, the second event is logged as ignored with `recent_history_equivalent` and does not call `/sync/history`;
- a repeated same-state `played` event inside 300 seconds is ignored;
- an explicit `unplayed` followed by `played` still reaches Trakt;
- a later legitimate rewatch still creates another play;
- Continue Watching, watched state, watchlist, dual-IMDb behavior and OAuth/profile state remain clean;
- authenticated Trakt write/429 pressure does not regress.

If a duplicate still appears while Bridge diagnostics show only one accepted history writer, isolate the native Trakt client path next rather than widening the Bridge dedupe window blindly.

## Rollback

Rollback is deterministic because schema remains `1`:

```text
v1.1.0-rc.1 exact digest
  -> v1.0.0 accepted immutable digest
```

No DB restore should be required for the code rollback itself, but the pre-canary backup remains mandatory.
