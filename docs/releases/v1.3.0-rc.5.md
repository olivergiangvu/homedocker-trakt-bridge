# v1.3.0-rc.5

This release candidate is a focused follow-up to RC4. It fixes canonical watched-state freshness during long-running normal use without changing RC4's history-lineage policy.

## What changed

- A successful AIO pull with `since=<current version>` already verifies Trakt `/sync/last_activities`.
- RC5 refreshes the persisted canonical watched snapshot timestamp when, and only when, the stored snapshot version exactly matches that authoritative version.
- The watched membership set itself is not modified by this verification.
- A version mismatch does not refresh the snapshot and still requires the normal changed-state/full watched path.

## Why RC5 is needed

RC4 intentionally rejects stale canonical snapshots after `CANONICAL_HISTORY_MAX_AGE_SECONDS` (900 seconds by default). Without RC5, a quiet Trakt account could keep returning the same version on healthy pulls while the canonical snapshot still aged past 15 minutes. A later stale single-item `played` echo could then fail open and create a fresh Trakt `watched_at`, reordering old history.

RC5 makes snapshot freshness reflect the last successful authoritative version verification rather than only the last full watched-set transfer.

## Safety and compatibility

- No extra Trakt history/watched write is added.
- No additional watched-set fetch is required when the version is unchanged.
- AIO SQLite remains read-only.
- Bridge DB schema remains 1.
- RC4 event-time evidence, 10-second fanout cohort suppression, same-state history guards, manual Mark Watched/Unwatched preservation, native bulk marks, and compare-only reconciler behavior are unchanged.

## HomeDocker qualification plan

RC5 replaces RC4 as the long-soak candidate.

After exact-digest canary cutover:
1. verify exact image/version/schema, one profile, restart 0, OOM false, and read-only AIO mount;
2. verify canonical snapshot freshness survives beyond 15 minutes while Trakt version remains unchanged;
3. run controlled Mark Watched/Unwatched and genuine playback checks;
4. run a fresh 48-hour natural-use soak with corrected delivery re-sampling and RC4/RC5 guard counters.

Public defaults remain unchanged; `AIO_HISTORY_ECHO_GUARD=false` unless explicitly enabled.
