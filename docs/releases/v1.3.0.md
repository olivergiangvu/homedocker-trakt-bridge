# HomeDocker Trakt Bridge v1.3.0 — Stable

**Release scope:** promotion of the production-proven `v1.3.0-rc.6` runtime to `v1.3.0` without any application logic, schema, dependency, Dockerfile or AIOStreams changes after RC6. Only Bridge `APP_VERSION`/`package.json` change from `1.3.0-rc.6` to `1.3.0`; existing read-only ops monitors and documentation are retained.

## Features in v1.3

- **Native Trakt precedence / AIO gap detection:** opt-in `AIO_RECONCILER_MODE=compare` performs authenticated Trakt GET only for settled, exact-sink AIO local playback candidates. A matching same/newer Trakt state wins; ambiguous/unavailable comparisons fail closed. **Never writes Trakt recovery history, never edits AIO SQLite.**
- **Watched/history echo protections (RC2–RC5):** optional evidence-guarded AIO `played/unplayed` echo and cohort/history-lineage protection. Manual marks, legitimate rewatches and native Trakt activity remain allowed; guard defaults unchanged.
- **RC6 playback and rate-limit hardening:** near-terminal (≥99%) pause and inconsistent unfinished stop are ignored rather than converted to false watched; legitimate completed stop follows existing 90%/played semantics. Authenticated Trakt pacing, Retry-After and read/write cooldown family isolation remain unchanged.
- **Optional canonical freshness:** `CANONICAL_ON_DEMAND_VERIFY=false` by default; no speculative extra GET traffic.
- **Rolling AIO compatibility:** dedicated read-only identity-drift, event-pulse and Jellyfin Resume/NextUp contract audit scripts. AIOStreams stays on upstream `ghcr.io/viren070/aiostreams:latest` and can upgrade independently.

## Actual HomeDocker RC6 production evidence (2026-10-13)

- Bridge health/readiness `ok/ready`, DB schema `1/1`, one connected profile.
- 24h observed Bridge event window bounded and covered; v2 monitor showed 464 playback events, 105 successful pulls, 2 stale pulls. Event log reports can miss external native-client writes or HTTP errors without explicit status fields.
- Compare-only: eight settled cases — three `trakt_same_or_newer`, five `trakt_stale_candidate`, all five with Trakt progress behind AIO by **≤2 minutes**. No writeback was requested or authorized.
- The stale mixed IMDb NextUp dual-card regression was resolved on all affected clients by one supported AIO Jellyfin **series preference** change. Known exact-scope drift monitor reports `MITIGATED_BY_DROP` and `attention=0`; 18 watched/resume episode rows preserved.
- The read-only rolling contract captured one 50-item Jellyfin NextUp and Resume page: `PASS_CAPTURED_CHECKS`, no duplicate verified-alias cards, Bridge readiness true. Nine opaque SeriesIds and uncaptured pages are limitations, not proof of library-wide completeness.

**No claim:** this evidence does not independently demonstrate a live near-terminal 99% playback, native-Trakt double-writer absence on every client, a full 72h soak or a physical-hardware restore rehearsal. The automated regression suite covers these boundaries. Publish/deploy remains conditional on release CI, immutable digest acceptance, host backup and live rollback readiness.

## RC7 identity / dual-IMDb fix — precisely what survives this Stable upgrade

**There are two distinct layers; neither should be described as an automatic code fix in the Stable image:**

1. **Operational fix already applied and verified on HomeDocker:** AIOStreams' supported Jellyfin series `dropped` preference suppresses the older `tt44094505` timeline, while the Trakt canonical `tt44051354` timeline and S01E10 resume remain. All 18 historical episode rows were kept. This preference persists in AIO's own database across **Bridge-only** container image upgrades; it is **not** baked into the Bridge image and may be invalidated if playback under the obsolete alias causes AIO to undrop it.
2. **RC7 tools included in this repository release source:** `scripts/monitor-identity-drift.py` and `scripts/audit-rolling-aio-contract.py`, with regression tests, examine Bridge/AIO identity and Jellyfin NextUp without writes. Because the production Dockerfile only copies `src/` and `package.json`, these Python scripts are **host-side operational tools**, not executable utilities inside the Bridge image. They do not automatically rewrite identities.

**Stable deployment acceptance:** the patched HomeDocker deployment helper (main branch, post-tag operator tooling) checks that the documented alias pair has zero drift attention and retained canonical history, with either an effective `MITIGATED_BY_DROP` preference or a genuine `SINGLE_TIMELINE` after the obsolete alias disappears, **both before and after replacing Bridge**. It does not require the user to keep S01E10 unfinished forever. It aborts/attempts rollback if this exact known mitigation is missing; no AIOStreams source edits, automatic re-drop actions, direct SQLite writes or Trakt history rewrites are permitted.

**Permanent cross-provider normalization** (which would prevent all alias-collision recurrences without depending on AIO's dropped preference) has **not** been implemented or claimed by `v1.3.0`. It requires a separate design, real client evidence and its own release qualification. The one-time repair PR #85 remains archived unmerged.

## Compatibility and defaults

```env
PULL_IDENTITY_MODE=trakt
AIO_RECONCILER_MODE=off
CANONICAL_ON_DEMAND_VERIFY=false
```

On the **qualified HomeDocker installation only**, preserve its already-enabled `AIO_RECONCILER_MODE=compare`; do **not** enable recovery writeback or change the 2s compare tolerance. Keep existing RC6 settings, sink identity, exact mounts, reverse proxy and Trakt authorization unchanged. Database schema stays `1`; no migration or watched-history replay. Native Trakt clients remain supported. Keep AIOStreams on `latest` independent of the Bridge digest.

## Explicitly excluded from stable v1.3

- **Recovery writeback / auto-repair**: requested future Phase B in Issue #70, not implemented or enabled. Stale candidates are **diagnostic only**; this is not a regression of a promised v1.3 capability.
- AIO upstream source/image forks; direct SQLite writes or automatic alias drop actions.
- Automated deletion of duplicate Trakt history, modification of legitimate rewatch records, forced native Trakt disablement.
- Any prerequisite AIOStreams pin to a historical digest.
