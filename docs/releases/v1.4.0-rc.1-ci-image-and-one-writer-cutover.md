## CI artifact contract (7 days)

On Draft #136 **pull-request runs only**, GitHub CI first runs all Node/Python/shell/Compose tests, builds the existing production Dockerfile, checks image size and starts an isolated synthetic /health + /readiness smoke. Only afterward CI tags the runner image to a unique v1.4.0-rc.1-ci-<checkout-sha> image and produces:

- `bridge-rc1.docker.tar`: `docker save` output for a CI-only image tag, with no mounted data volume or runtime secrets.
- `SHA256SUMS`: SHA-256 over the image archive; CI verifies the digest immediately.
- `IMAGE-METADATA.txt`: checkout commit SHA, PR head SHA, CI tag, local Docker image ID, and explicit unpublished registry-digest state.

Workflow uploads these as the time-limited GitHub Actions artifact `v140-rc1-ci-image-<run-id>`. The *Docker archive checksum* ensures archive-byte integrity, **not** an immutable GHCR/OCI manifest digest, image signature, or published release. On pull_request GitHub usually checks out a synthetic merge commit; `source_checkout_sha` is the exact archive source, while `source_pr_head_sha` separately identifies PR branch HEAD. Never falsely label those SHAs identical. No GHCR push or stable tags. A successful upload does NOT mean the image is installed anywhere.

## One-time read-only One-Writer Gate (after routine backup, not an additional backup audit)

Use the reviewed RC.1 source checkout, pinned by the exact PR HEAD SHA, and run only:

```bash
sudo python3 -B scripts/audit-v140-rc1-one-writer.py
```

This uses Docker inspection only: exact RC6 image/config, Compose ownership, shared Bridge `/app/data` source and whether ANY other running container mounts the same source. It reports fixed boolean/aggregate results, never credentials, file paths, IDs or mount names. It does not read/validate OneDrive again, restart services, read SQLite, create a backup, load RC.1 image or authorize a cutover. PASS here means only no obvious second Docker container shares the Bridge DB. It does not prove absence of non-Docker writers, which must remain under operator control.

Do not run this check repeatedly as a periodic task; once shortly before an approved cutover suffices. If it returns STOP_REVIEW, do not try to force a rollout.
## Download/verify later (ONLY after the operator separately approves host artifact transfer)

GitHub Actions PR run page identifies its own run ID and matching artifact name. In a private, non-productive scratch directory the operator may later use:

```bash
gh run download <RUN_ID> -R olivergiangvu/homedocker-trakt-bridge \
  -n v140-rc1-ci-image-<RUN_ID> -D <PRIVATE_SCRATCH_DIRECTORY>
cd <PRIVATE_SCRATCH_DIRECTORY>
sha256sum -c SHA256SUMS
```

**Do not run `docker load`, `docker tag`, `docker compose up`, copy secrets or attach the running RC6 volume automatically.** Do not treat an artifact as a public registry image or as a signed release. If the scratch artifact expires, run a new reviewed PR CI build; never grab a mutable `latest` tag.
