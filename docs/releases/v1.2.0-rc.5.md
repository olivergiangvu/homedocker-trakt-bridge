# v1.2.0-rc.5 — detect-only AIO local-state reconciler

Status: **release candidate / HomeDocker detect-only canary**.

Stable remains `v1.1.0`. The current HomeDocker runtime canary remains rc.4 until this detector is explicitly enabled and qualified.

## Why rc.5 exists

HomeDocker cross-client testing isolated a Jellyfin UserData handoff gap in AIOStreams 2.35.9.

A Strand playback test produced:

```text
AIO local watch_state   443904 ms / 07:23
Trakt native state      443904 ms / 07:23
Bridge deliveries       unplayed only
Bridge start/pause/stop none
VidHub resume           07:23
```

Source audit showed that AIOStreams' UserData route can record `PlaybackPositionTicks` locally as a stop without dispatching that stop to watch-state addons. Native Trakt covered Strand in the observed case, but a Jellyfin-only client using the same route could leave Trakt stale.

rc.5-A observes this gap without patching AIOStreams.

## What changes

An optional Bridge-side reconciler can read the AIOStreams SQLite database through a read-only mount.

When `AIO_RECONCILER_MODE=detect`:

- AIO SQLite is opened with `readOnly` and `PRAGMA query_only=ON`;
- only local, unfinished movie/episode rows with a real resume position are considered;
- the detector waits for a configurable grace period;
- it checks for a nearby queued AIO `start`, `pause`, or `stop` delivery;
- a missing playback delivery is recorded as a reconciliation candidate;
- the cursor and row watermark are stored only in Bridge `media_cache`;
- the first enabled run establishes a baseline and does not replay historical AIO state.

The detector requires exactly one connected Bridge profile and fails safe otherwise.

## What rc.5-A does not do

- does not modify AIOStreams code;
- does not modify the AIOStreams database;
- does not change AIOStreams `WATCH_STATE_*` settings;
- does not call Trakt from the reconciler;
- does not synthesize a playback event;
- does not write Trakt;
- does not change rc.4 transport, rate-limit lanes, watermarks or semantic history dedupe.

This phase is intentionally observation-only.

## Configuration

Disabled by default:

```env
AIO_RECONCILER_MODE=off
```

HomeDocker detect canary:

```env
AIO_RECONCILER_MODE=detect
AIO_DB_PATH=/aio-data/db.sqlite
AIO_RECONCILE_INTERVAL_SECONDS=15
AIO_RECONCILE_GRACE_SECONDS=30
AIO_RECONCILE_MAX_ROWS=100
```

Mount AIO data read-only into the Bridge container:

```yaml
volumes:
  - trakt_bridge_data:/app/data
  - /var/lib/docker/volumes/aiostreams_data/_data:/aio-data:ro
```

## Qualification plan

1. confirm exact rc.5 image, health/readiness, schema 1 and zero unexpected restarts;
2. enable detect mode with the AIO volume mounted read-only;
3. verify first-run baseline creates no historical candidate flood;
4. play through a normal client path that emits stop/pause and confirm the detector classifies it as covered;
5. reproduce a UserData-only progress update and confirm `candidate_missing_aio_playback_delivery`;
6. verify AIO DB remains unchanged by the Bridge and no reconciler Trakt requests occur;
7. restart the Bridge and confirm the persisted cursor prevents duplicate detection.

## Next phase

Only after detect-mode evidence is accepted should rc.5-B be considered.

A write-capable reconciler must compare the candidate against current Trakt playback before synthesizing any stop. If native Trakt already holds the same or newer state, it must skip the write. Native Trakt coexistence remains a hard requirement.
