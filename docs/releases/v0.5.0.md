# HomeDocker Trakt Bridge v0.5.0

Status: **release-ready — HomeDocker canary accepted on 2026-10-01**.

v0.5.0 is an integration and recovery hardening release. It keeps the v0.4.0 data model and AIOStreams representation while adding end-to-end recovery coverage and clearer Trakt authorization failure semantics.

## Highlights

- local HTTP integration harness for Trakt API behavior without external-network tests
- OAuth `401 -> refresh -> retry` coverage
- OAuth `invalid_grant -> reconnect_required` behavior
- unusable OAuth credentials are cleared locally after `invalid_grant`
- `/status` exposes `profile.connectionState` and `profile.reconnectRequired`
- retry/idempotency survives SQLite reopen and service restart
- Trakt `429` preserves `Retry-After` and remains retryable
- `429` / upstream `5xx` bounded stale pull fallback coverage
- stale-window expiry fails closed
- Trakt `404` provider alias fallback coverage
- Trakt `420` / `422` deterministic classification coverage
- pagination safety-cap fail-closed coverage
- concurrent identical pulls are coalesced
- authoritative watched/watchlist state fails closed when incomplete
- production dual-IMDb regression fixture remains locked to Trakt spelling in `PULL_IDENTITY_MODE=trakt`
- SQLite backup -> restore -> restart coverage preserves tokens, processed-event idempotency and cache

## Compatibility

v0.5.0 intentionally keeps:

```text
DB schema              1
pull representation    watch-state-v0.3.6
pull cache namespace   pull-state:v5:*
PULL_IDENTITY_MODE     trakt (HomeDocker recommendation)
```

No database migration and no cache purge are required from v0.4.0.

## Authorization recovery

When Trakt rejects a refresh token with OAuth `invalid_grant`:

```text
invalid_grant
  -> bridge clears unusable encrypted OAuth tokens
  -> auth event state becomes reconnect_required
  -> /status profile.connectionState = reconnect_required
  -> /readiness = setup_required
  -> operator reconnects Trakt
  -> successful OAuth stores fresh tokens and state returns to connected
```

The bridge does not retry an invalid authorization grant indefinitely and does not keep reporting the profile as connected after Trakt has rejected the grant.
