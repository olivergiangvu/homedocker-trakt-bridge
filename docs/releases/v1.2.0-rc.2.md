# v1.2.0-rc.2 — Pre-resolution stale protection

Status: **release candidate / HomeDocker canary only**.

`v1.1.0` remains the stable production release.

## Why rc.2 exists

The first rc.1 VidHub canary captured a new failure boundary:

- VidHub paused correctly at 11.84%.
- AIOStreams stored the local 11.84% state and delivered the pause.
- Bridge failed before scrobbling because Trakt returned `429` on the public episode metadata lookup:
  `/shows/285217/seasons/1/episodes/2`
- The response carried `Retry-After: 65` and no `X-Ratelimit` bucket metadata.

rc.1's canonical playback watermark was recorded only after successful media resolution. Therefore a newer event that failed in the resolver could still leave an older queued retry eligible to overtake it later.

## What changes

### Source playback watermark before resolution

For `start`, `pause`, and `stop`, rc.2 now records a source-identity watermark before any Trakt media-resolution request.

For episodes, the primary source identity is the AIOStreams `videoId` (with a meta/season/episode fallback).

This means:

```text
newer pause arrives
  -> source watermark advances
  -> episode resolver gets 429
  -> older stop retries later
  -> ignored as stale before another resolver call
```

The existing canonical Trakt-item watermark remains after successful resolution as a second protection layer.

### Public metadata Retry-After cooldown

Public Trakt metadata requests now have their own persisted local cooldown.

After a public metadata 429:

- `Retry-After` is honored;
- another resolver call during the window is rejected locally;
- the cooldown survives client reconstruction/restart through the existing SQLite cache;
- authenticated pull and write lanes are not unnecessarily blocked by this public lookup throttle.

## What does not change

- v1.1 semantic history dedupe remains unchanged.
- rc.1 authenticated read/write/shared cooldown handling remains unchanged.
- `PULL_IDENTITY_MODE=trakt` remains recommended.
- `HISTORY_DEDUPE_SECONDS=300` remains recommended.
- DB schema remains `1`.
- Native Trakt stays enabled on supported clients during HomeDocker qualification.
- Pause-422 recovery remains deferred until a real 422 reason is captured.

## HomeDocker acceptance

With native Trakt enabled on VidHub and Strand:

- health reports `1.2.0-rc.2`;
- readiness remains ready, schema `1`, connected profile count unchanged;
- a newer playback event that hits a public resolver 429 still protects against an older retry;
- repeated resolver attempts during `Retry-After` are locally cooled down rather than re-hitting Trakt;
- once the resolver cooldown clears, the latest event can converge to Trakt;
- no stale retry rewinds resume state;
- no regression appears in semantic history dedupe, watchlist, OAuth or pull identity.
