# v1.2.0-rc.7 — position-aware HomeDocker coverage detector

Status: **release candidate / HomeDocker detect-only canary**.

Stable remains `v1.1.0`. rc.6 remains the current HomeDocker runtime canary until rc.7 is published and explicitly enabled.

## Why rc.7 exists

The rc.6 VidHub covered-path test found a detector false-negative on the actual item `e|tt36885662:1:3`.

Observed:

```text
HomeDocker start      651281 ms
HomeDocker stop       651281 ms
stop created_at       1791139920074

later AIO local row   651269 ms
row updated_at        1791139985235

delta in time         ~65.16 s
delta in position     12 ms

later AIO event       unplayed / positionMs 0
unplayed created_at   1791139985218
```

The valid stop had already been delivered to HomeDocker, but rc.6 only searched +/-15 seconds around the final `watch_state.updated_at`. The later generic UserData/unplayed update therefore made the final row look uncovered.

## What changes

rc.7 keeps the rc.6 300-second per-item settlement model and adds position-aware delivery correlation:

- coverage is limited to the configured HomeDocker sink;
- only delivery rows with `status='delivered'` qualify;
- only `start`, `pause`, and `stop` qualify;
- the delivery JSON body must contain a positive `positionMs`;
- delivery position must match the final AIO row within `AIO_RECONCILE_POSITION_TOLERANCE_MS` (default 2000 ms);
- matching can look backward up to `AIO_RECONCILE_COVERAGE_LOOKBACK_SECONDS` (default 180 s);
- a tight 15-second forward allowance remains for minor scheduling skew.

This lets a later generic UserData row remain covered by an earlier valid stop only when the same HomeDocker sink already delivered essentially the same playback position.

## Safety

rc.7 remains detect-only:

- no AIOStreams code/config changes;
- AIO SQLite remains read-only;
- no reconciler Trakt reads or writes;
- no synthetic playback events;
- no Bridge DB migration;
- delivery rows in error/pending state never count as coverage;
- an older delivered event at a materially different playback position never counts as coverage.
