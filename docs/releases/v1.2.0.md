# v1.2.0 — Native-Trakt hardening and restart-safe AIO diagnostics

Status: **stable**.

`v1.2.0` promotes the fully qualified `v1.2.0-rc.7` HomeDocker canary to the stable release line. No new production behavior is added after the accepted rc.7 logic; the promotion changes version metadata and stable documentation only.

## What this release improves

### Playback ordering and native-Trakt coexistence

The v1.2 line hardens playback writes when native Trakt and AIOStreams are both active:

- source playback watermarks are persisted before metadata resolution so an older retry cannot overtake a newer playback transition;
- normal movie/episode playback and history writes use Trakt-compatible provider IDs directly instead of blocking on public metadata resolution;
- episode scrobbles use the Trakt show + season + episode transport shape;
- event ordering follows event time rather than progress, so a legitimate newer backwards seek remains valid;
- the existing v1.1 semantic history dedupe remains in place.

### Rate-limit isolation

Authenticated writes retain global pacing, but ambiguous/headerless Trakt `429` responses are isolated by write family:

- scrobble;
- history;
- watchlist.

Explicit shared/all-write rate-limit metadata still applies conservatively across the relevant authenticated write surface. A history-remove throttle therefore cannot unnecessarily freeze latency-sensitive playback scrobbles.

### Optional AIO local-state reconciler

v1.2 includes the optional detect-only AIO reconciler qualified through rc.5-rc.7.

It:

- reads the AIOStreams SQLite database through a read-only mount;
- inspects only unfinished local movie/episode resume rows;
- persists one pending candidate per user/persona/item;
- coalesces newer same-item local rows while preserving the original `firstSeenAt`;
- waits for `AIO_RECONCILE_QUIET_SECONDS` before terminal classification;
- resolves coverage only against the configured HomeDocker sink;
- accepts only delivered `start`, `pause`, or `stop` playback rows with a positive equivalent `positionMs`;
- uses bounded position-aware lookback so a later generic UserData row can still be covered by an earlier valid stop;
- never calls or writes Trakt;
- never writes AIOStreams.

The reconciler remains **disabled by default**.

## Recommended configuration

For clients that may also use native Trakt:

```env
PULL_IDENTITY_MODE=trakt
HISTORY_DEDUPE_SECONDS=300
```

The public default for the optional reconciler remains:

```env
AIO_RECONCILER_MODE=off
```

When explicitly enabling detect-only mode, mount the AIOStreams data directory read-only and configure the exact sink identity where possible.

## Compatibility

v1.2.0 intentionally keeps:

- DB schema `1`;
- the existing pull representation and cache namespaces;
- existing OAuth/profile state;
- native-Trakt coexistence mode;
- v1.1 semantic history dedupe behavior.

No database migration or pull-cache purge is required from v1.1.0.

## Upgrade

Before upgrading, back up:

- `bridge.db`;
- `.env`;
- Compose configuration;
- reverse-proxy configuration.

For production, pin the immutable v1.2.0 digest published and smoke-tested by the release workflow rather than following `latest`.
