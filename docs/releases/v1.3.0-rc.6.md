# HomeDocker Trakt Bridge v1.3.0-rc.6 — staging notes

**Status:** draft canary candidate. No production cutover or stable promotion authorized by this document.

## What changes
1. **Terminal pause HTTP 422:** Trakt responds `Progress is 99.982%. Use stop to scrobble.` AIO `pause >=99%` is deliberately ignored, not transformed into `stop` or `history:add`. An inconsistent `stop played=false >=99%` is also ignored. Normal `stop played=true` keeps the RC5 completion transport. No AIO DB mutation, replay, or change to 90% threshold.
2. **Authenticated Trakt 429:** on true upstream HTTP 429, persist a profile-specific cooldown in the existing DB cache. Respect `Retry-After`; use configurable 30s fallback (max 1h). During cooldown, fast-fail with HTTP429/Retry-After instead of hammering Trakt. Native device clients cannot be serialized by this Bridge. This is not a complete rate limiter.
3. **Canonical freshness opt-in:** `CANONICAL_ON_DEMAND_VERIFY=false` by default. When enabled, an otherwise unguarded single history mark may trigger Trakt `pullState` before canonical re-evaluation, *only if* a saved versioned snapshot is stale. In-process profile single-flight and min 120s recheck interval reduce amplification. On failed verification, the RC5 guard stays fail-open and real marks are not blindly suppressed.
4. **Tests:** boundaries at 80/85/89.9/90/98.9/99/99.982/100%, profile cooldown and isolation, 422 noncooldown, canonical singleflight/failure throttle.

## Explicitly not changed
- RC5 pinned container image and existing Docker Compose, port/host nginx, AIO SQLite, Trakt history.
- The stale 900s threshold remains; increasing it without newer canonical evidence can suppress genuine manual marks.
- AIO `WATCH_STATE_PULL_INTERVAL` remains unchanged. Soak showed 44.3% snapshot samples older than 15 min. An opt-in verifier reduces **decision-time** stale exposure only during mark handling; it does **not** change wall-clock stale-sample percentages by itself.
- Split IMDb identity for *OK! Let's Get Divorced* and Android native double-writers remain separate workstreams.

## Verification and release gates
1. PR CI: `npm run check`, `npm test`, Docker build, image size, health/readiness and Compose validation must pass.
2. No schema migration; review diff of `src/migrations.mjs` unchanged.
3. Build/push immutable GHCR image tagged RC6 from the reviewed commit; pin **digest**, not moving tag.
4. Before a canary, take backup of compose/env/Bridge SQLite and record the RC5 digest + rollback command. Avoid capturing secrets in issues/logs.
5. Dry-run/canary with `CANONICAL_ON_DEMAND_VERIFY=false`; verify no unwanted watched, no 422 near-terminal pauses, and retry-after behavior. Only then enable the canonical opt-in and compare number of verifications, 429, guard variants, and real manual marks.
6. Revert to pinned RC5 digest on regression. Do not roll back AIO database or replay Trakt history unless separate evidence and backups justify it.

**Known limitation:** Because AIO clients and native Trakt Android TV apps can independently write the same history, fixing Bridge pause/429/canonical evidence alone cannot guarantee absence of native double-history. Do not disable native Trakt globally unless the client is independently verified to send playback completion through AIO.
