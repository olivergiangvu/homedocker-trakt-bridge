# v1.4.0 Unified Gateway — AUTO ON product decision (2026-10-20)

**Status:** proposed source-only change, review/CI required, no HomeDocker deployment or stable publication authorization.

## Operator product decision

The unified Trakt Bridge/Gateway should **attempt safe NextUp alias filtering by default** whenever a source is explicitly and validly provisioned. Do not require a one-time manual Turn ON for every new source. Preserve an immediate persistent **Turn OFF** operator kill switch. Known functional gaps can be fixed in subsequent stable versions, but do not label those gaps as solved.

## Exact semantics

1. Bridge/Gateway listener provisioning is separate. `JELLYFIN_GATEWAY_ENABLED` stays `false` when no source is configured, and remains an explicit operator-controlled environment setting; no automatic listener, public port, nginx rewrite or client ingress.
2. Once `jellyfinGatewayEnabled=true`, exact 24-hex Bridge profile, mapped Jellyfin UserId and configured upstream URL are present, the same Bridge dashboard/source is **AUTO ON** if there is **no matching preference** in the existing `media_cache`. Reading AUTO ON does not create a database row.
3. A stored explicit `{enabled:false}` for the **exact profile + source kind + upstream URL + user** immediately disables normalization. OFF persists across restarts. Explicit Turn ON stores `{enabled:true}`. Malformed preference values fail OFF; a missing/incomplete mapping fails OFF.
4. Source/user changes never inherit the old scoped explicit ON/OFF preference. A new fully provisioned source uses its own AUTO ON default. Runtime `/Users/Me` validation on every eligible normalization request still requires the exact mapped user; no cross-user graph, guessed alias or shared token.
5. Only safely qualified GET `/Shows/NextUp` TV-series alias duplicate candidates are projected. Unknown, full, partially paged or ambiguous responses are original AIO passthrough; competing resumes, missing metadata or unverified IDs never justify dropping a card. The filtering policy does **not** correct all NextUp duplicates.
6. `/UserItems/Resume`, movies, global pagination beyond the proven page, off-window >200 candidate insertion, playback, streaming, Trakt history, AIO DB and the existing single Trakt writer are unchanged.
7. The UI shows AUTO ON by default when provisioned and offers Turn OFF/Turn ON; the switch does not change nginx, login, transport or clients.

## Mandatory review / operational release gates

- Tests: AUTO ON with no cache row, persistent OFF/ON, malformed preference and absent listener/profile, same-user and wrong-user, pagination pass-through, latency and error fallback, no watch-history events/writes.
- Dashboard must be clear that a listening Gateway or Auto ON **does not prove client traffic traverses Gateway**.
- Canary ingress for selected Odin and AIOStreams Desktop is not proven by this source change; QuickConnect/auth + Resume/playback continue to pass to AIO. Client-level success/limitations must be recorded truthfully before claiming a functional NextUp fix.
- Keep `V140_STABLE_RELEASE_HOLD` active until the v1.4 release charter and release workflow policy receive explicit review. No tag/GHCR push, no production bridge recreation, no Filter ON operation on RC2 and no nginx/client modifications from this change alone.
- Preserve the pinned RC2 checkout `65ced8ab827c79f03bff7a7668c243338e62f317`, CI artifact run `39227704790`, operator-verified archive SHA256 and image ID as protected rollback provenance.

## Release positioning

v1.4.0 can ship an AUTO ON, fail-open **best-effort** NextUp identity view with disclosed coverage limitations after required source and ingress acceptance. Remaining false-negative doubles can be fixed in later stable patch releases; cross-user leaks, unverified drops, breaking Trakt sync or unsafe release provenance are not acceptable deferred regressions.
