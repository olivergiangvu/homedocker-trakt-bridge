# v1.3.0-rc.1 — Trakt-aware compare-only AIO recovery

Status: **release candidate / compare-only canary**.

`v1.3.0-rc.1` begins the v1.3 guarded recovery work without adding any automatic recovery write. It preserves the fully qualified v1.2 detect path and adds a separate Trakt comparison queue for settled AIO local-state candidates that are missing an equivalent delivered HomeDocker playback event.

## What this RC adds

### Compare-only reconciler mode

Set:

```env
AIO_RECONCILER_MODE=compare
```

Compare mode keeps the v1.2 detector unchanged, including:

- read-only AIO SQLite access;
- unfinished local movie/episode rows only;
- exact HomeDocker sink matching;
- 300-second quiet-window settlement by default;
- restart-safe pending persistence;
- same-item coalescing with preserved `firstSeenAt`;
- position-aware delivered start/pause/stop coverage;
- delivered-only coverage semantics;
- no AIO writes.

Only a settled candidate classified as missing a HomeDocker playback delivery is placed onto the new Trakt comparison queue.

### Native-Trakt precedence

The comparison queue uses authenticated Trakt **GET** playback endpoints only.

A candidate is classified as:

- `trakt_same_or_newer` — native/current Trakt state already wins; no recovery candidate;
- `trakt_stale_candidate` — matching Trakt playback exists but is older and behind;
- `trakt_playback_missing_candidate` — no matching current Trakt playback exists;
- `trakt_compare_ambiguous` — media identity or match is not safe enough; fail closed.

A newer Trakt playback timestamp takes precedence even if its numeric progress is lower, so a legitimate newer backward seek is not overwritten by an older AIO row. Equivalent or ahead Trakt playback progress also suppresses recovery candidacy.

### Retry-safe reads

Transient Trakt GET failures and read/shared rate limits remain retryable with bounded backoff. They do not become terminal write decisions.

Compare mode uses the existing managed Trakt read/shared cooldown behavior and does not consume the scrobble/history/watchlist write lanes.

### Diagnostics

The bridge persists compare terminal markers separately from v1.2 detect settlement markers and exposes aggregate compare diagnostics through operational status:

- awaiting comparison;
- retrying;
- same/newer;
- stale candidate;
- missing candidate;
- ambiguous;
- latest decision.

## Safety

This RC intentionally contains **no Phase B writeback**.

In compare mode:

```text
writesTrakt=false
AIO SQLite=read-only
Trakt POST/PUT/DELETE=never used by reconciler
```

The public default remains:

```env
AIO_RECONCILER_MODE=off
```

Existing playback watermarks, history dedupe, rate-limit isolation, direct provider-ID transport, and native-Trakt coexistence behavior are unchanged.

DB schema remains `1`; no migration or pull-cache purge is required.

## HomeDocker canary target

For HomeDocker, RC1 should be enabled only as a compare-only observation canary after the exact published digest passes release smoke testing.

Recommended HomeDocker values remain:

```env
AIO_RECONCILER_MODE=compare
AIO_DB_PATH=/aio-data/db.sqlite
AIO_RECONCILE_INTERVAL_SECONDS=15
AIO_RECONCILE_GRACE_SECONDS=30
AIO_RECONCILE_QUIET_SECONDS=300
AIO_RECONCILE_COVERAGE_LOOKBACK_SECONDS=180
AIO_RECONCILE_POSITION_TOLERANCE_MS=2000
AIO_RECONCILE_SINK_NAME=homedocker-trakt-bridge
AIO_RECONCILE_SINK_INSTANCE_ID=e3fe3b0
AIO_RECONCILE_MAX_ROWS=100
```

Keep the AIO data mount read-only.

Canary acceptance should confirm:

- existing v1.2 detect behavior remains unchanged;
- only genuine missing-delivery candidates enter the compare queue;
- native Trakt same/newer state is classified correctly;
- older/behind Trakt playback is only observed as a candidate;
- missing Trakt playback is only observed as a candidate;
- ambiguous identity fails closed;
- Trakt read cooldowns remain retryable;
- no reconciler Trakt writes occur;
- restart preserves queued comparisons and terminal decisions remain exactly-once.
