# HomeDocker Trakt Bridge v1.4.0-rc.2 — Unified Gateway and integrated UI

**Release type:** GitHub Actions checksum-verified RC2 image archive (Draft PR), **NOT** a published/tagged Stable release. Production on HomeDocker remains the operator-verified **v1.4.0-rc.1** until a separately approved single-writer upgrade. Existing `V140_STABLE_RELEASE_HOLD` remains active.

## Product layout

One Bridge process, existing Trakt OAuth/profile/SQLite/one writer and Jellyfin-compatible API source (AIOStreams primary). An optional built-in Jellyfin Gateway shares the same Bridge process and verified Bridge identity graph. New responsive **Unified Gateway** panel lives on the existing authenticated admin/profile dashboard: activation readiness, Trakt→Bridge→AIO→Odin path, identity coverage, authenticated persistent ON/OFF control, conditional NextUp policy, Resume mode, since-restart traffic, fail-open signals, and read-only JSON diagnostics. There is no second dashboard or second Trakt writer.

## Clarified Jellyfin Gateway topology and real UI ON/OFF (2026-10-19)

**AIOStreams is the primary Jellyfin API source**. Remux or native Jellyfin are compatible backend types only where their authenticated `/Users/Me`, `/Shows/NextUp` and `/Items/{SeriesId}` contracts have been validated. Odin is ONE Jellyfin front-end client among others; identity normalization is client-agnostic, not an Odin plugin. This RC has one selected Jellyfin-compatible upstream per protected listener, not simultaneous three-source multiplexing and not generic transparency for a full Jellyfin client server.

**Three separate layers — no misleading one-click routing promise:**

1. **Source/Listener provisioned:** operator configures the desired backend URL, the exactly mapped Jellyfin user/profile, `JELLYFIN_GATEWAY_ENABLED=true`, and an explicitly reviewed, bounded ingress route. AIO remains the primary and original source, with no patch/fork. No public port 7101 by default.
2. **Identity Filter ON/OFF on existing Unified admin/profile UI:** authenticated POST with existing admin or mapped-profile setup key, strict same-origin browser guard; action writes only a namespaced Bridge `media_cache` preference with a long TTL and returns a redirect. It does NOT alter watch history, change a playback position, invoke Trakt APIs or restart Bridge. The Gateway checks the current preference for each NextUp request. **OFF = unmodified AIO/Remux/Jellyfin response; ON = attempt verified, fail-open NextUp projection.** Initial preference OFF even after provisioning, persisted across restarts. A source/user/url change automatically gets a different preference scope and remains OFF until explicitly enabled for that new backend.
3. **Client ingress routing:** nginx/client already needs to send eligible Jellyfin NextUp requests through the Gateway adapter. The UI switch cannot reroute Odin/Swiftfin/Remux clients by itself and never changes native nginx. Once the protected route is installed, the switch controls filtering for whatever compatible Jellyfin client uses that route.

**Current functional limit:** verified-show/episode `/Shows/NextUp` only. The existing filtering engine does **not** yet normalize movies across distinct IMDb IDs or the `/UserItems/Resume` movie stream; do not advertise complete show+movie dedup. Independent, strictly verified movie identity mapping and safe full pagination must be qualified before enabling those response families.

**Status UI:** one shared admin/profile dashboard displays listener provisioning, effective filter ON/OFF, backend type, identity coverage, read-only metrics, and a directly working `Turn ON / Turn OFF` form. Button is disabled with an explicit setup prerequisite when listener, source or same-user mapping is not ready.

## NextUp `StartIndex=0` — conservative bounded improvement

`JELLYFIN_GATEWAY_FIRST_PAGE_MODE=short_first_page_only` allows the already opt-in Gateway to normalize a verified alias response **only** when Odin requests exactly `StartIndex=0&Limit=N`, N=2..50, no other query parameters, upstream returned 2..N-1 items, `TotalRecordCount===Items.length`, optional `Count` matches, upstream returned `StartIndex=0` if set, the exact configured Jellyfin user identity matches authenticated upstream `/Users/Me`, complete series metadata resolves and a verified graph says two distinct IMDb spellings are the same Trakt show. Conflicting active resumes and ambiguous responses remain untouched.

Every full first page, `StartIndex>0`, unknown query, incomplete count, wrong user, failed metadata, unverified graph or bad upstream remains AIO passthrough. This rule avoids rewriting arbitrary paged totals. `JELLYFIN_GATEWAY_FIRST_PAGE_MODE=off` additionally disables all explicit `StartIndex=0` normalization. Ordinary unpaged eligible requests preserve their prior behavior. `Resume` is never normalized. No watch-state, AIO SQLite or Trakt history mutation is introduced.

**Additional safety completion (Draft follow-up):** Limit-only requests are not necessarily complete even without `StartIndex`. A full `Limit` page, missing/inconsistent `TotalRecordCount` or `Count`, unexpected response `StartIndex`, and unrecognized selectors now pass through without rewriting pagination. The Unified UI exposes an anonymous "Unsafe unpaged passed through" counter since restart. This is deliberately conservative: some genuine duplicates remain visible when completeness cannot be proved.

**Operator activation:** See `docs/operations/v140-rc2-gateway-ui-activation.md` for separate RC2 promotion, one-time internal Gateway listener provisioning, authenticated ON/OFF smoke test, and **separately authorized client ingress**. This Draft follow-up does not change any running server or nginx route.

**Limit:** The prior actual Odin shadow example requested 20 records and supplied no positive alias candidate. No evidence yet demonstrates the new conservative rule will normalize that particular real page; **this is not a declaration that client-visible Odin duplicates are solved**. A genuine paged request with `Items.length===Limit` always passes through unchanged. Activation and Odin route qualification remain separate opt-in stages.

## Security and operations

- `JELLYFIN_GATEWAY_ENABLED=false`, `JELLYFIN_GATEWAY_LEGACY_IMPORT=off`, `JELLYFIN_GATEWAY_RESUME_PASSTHROUGH=false` remain the packaging and initial HomeDocker defaults.
- No unreviewed host publication of Gateway port 7101; Docker Compose continues to expose only `127.0.0.1:7000:7000`. Do not expose 7101 to WAN or rewrite nginx until the exact one-user route and network policy are explicitly approved.
- One verified Trakt writer; no side-by-side RC2 and RC1 with the same `/app/data` or OAuth credentials.
- Built on the already reviewed RC1 source and the ops-only rollout branch; prior RC6 rollback archive and automated restic backups are reused, not audited repeatedly.
- The v1.4 tag release workflow **still fails intentionally**. The temporary Actions artifact is a Docker archive with SHA-256 proof, not a signed OCI registry digest or stable release.
