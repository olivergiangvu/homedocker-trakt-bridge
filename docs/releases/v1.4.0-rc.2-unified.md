# HomeDocker Trakt Bridge v1.4.0-rc.2 — Unified Gateway and integrated UI

**Release type:** GitHub Actions checksum-verified RC2 image archive (Draft PR), **NOT** a published/tagged Stable release. Production on HomeDocker remains the operator-verified **v1.4.0-rc.1** until a separately approved single-writer upgrade. Existing `V140_STABLE_RELEASE_HOLD` remains active.

## Product layout

One Bridge process, existing Trakt OAuth/profile/SQLite/one writer and AIOStreams connection. An optional built-in Jellyfin Gateway shares the same Bridge process and verified Bridge identity graph. New responsive **Unified Gateway** panel lives on the existing authenticated admin/profile dashboard: activation readiness, Trakt→Bridge→AIO→Odin path, identity coverage, conditional NextUp policy, Resume mode, since-restart traffic, fail-open signals, and read-only JSON diagnostics. There is no second dashboard or second Trakt writer.

## NextUp `StartIndex=0` — conservative bounded improvement

`JELLYFIN_GATEWAY_FIRST_PAGE_MODE=short_first_page_only` allows the already opt-in Gateway to normalize a verified alias response **only** when Odin requests exactly `StartIndex=0&Limit=N`, N=2..50, no other query parameters, upstream returned 2..N-1 items, `TotalRecordCount===Items.length`, optional `Count` matches, upstream returned `StartIndex=0` if set, the exact configured Jellyfin user identity matches authenticated upstream `/Users/Me`, complete series metadata resolves and a verified graph says two distinct IMDb spellings are the same Trakt show. Conflicting active resumes and ambiguous responses remain untouched.

Every full first page, `StartIndex>0`, unknown query, incomplete count, wrong user, failed metadata, unverified graph or bad upstream remains AIO passthrough. This rule avoids rewriting arbitrary paged totals. `JELLYFIN_GATEWAY_FIRST_PAGE_MODE=off` additionally disables all explicit `StartIndex=0` normalization. Ordinary unpaged eligible requests preserve their prior behavior. `Resume` is never normalized. No watch-state, AIO SQLite or Trakt history mutation is introduced.

**Limit:** The prior actual Odin shadow example requested 20 records and supplied no positive alias candidate. No evidence yet demonstrates the new conservative rule will normalize that particular real page; **this is not a declaration that client-visible Odin duplicates are solved**. A genuine paged request with `Items.length===Limit` always passes through unchanged. Activation and Odin route qualification remain separate opt-in stages.

## Security and operations

- `JELLYFIN_GATEWAY_ENABLED=false`, `JELLYFIN_GATEWAY_LEGACY_IMPORT=off`, `JELLYFIN_GATEWAY_RESUME_PASSTHROUGH=false` remain the packaging and initial HomeDocker defaults.
- No unreviewed host publication of Gateway port 7101; Docker Compose continues to expose only `127.0.0.1:7000:7000`. Do not expose 7101 to WAN or rewrite nginx until the exact one-user route and network policy are explicitly approved.
- One verified Trakt writer; no side-by-side RC2 and RC1 with the same `/app/data` or OAuth credentials.
- Built on the already reviewed RC1 source and the ops-only rollout branch; prior RC6 rollback archive and automated restic backups are reused, not audited repeatedly.
- The v1.4 tag release workflow **still fails intentionally**. The temporary Actions artifact is a Docker archive with SHA-256 proof, not a signed OCI registry digest or stable release.
