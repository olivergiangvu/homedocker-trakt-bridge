# HomeDocker Trakt Bridge v0.9.0 RC

Status: **release-candidate hardening**.

v0.9.0 is the final pre-1.0 hardening line. It intentionally avoids watch-state feature changes and focuses on release-artifact reproducibility, deployment parity and supply-chain visibility.

## RC goals

- deploy the published GHCR image instead of rebuilding source on the target host
- smoke-test the exact image digest pushed by the release workflow
- keep a source-build Compose override only for development
- publish stable semver tags plus `latest`
- publish SBOM and provenance metadata for release images
- pin the Node base image digest and monitor Docker/GitHub Actions updates
- keep runtime data compatibility with v0.5.0
- verify fresh install, upgrade, restart and rollback using release artifacts

## Compatibility target

```text
DB schema              1
pull representation    watch-state-v0.3.6
pull cache namespace   pull-state:v5:*
PULL_IDENTITY_MODE     trakt
```

No DB migration or cache purge is planned for v0.5.0 -> v0.9.0.

## HomeDocker RC acceptance

Before tagging `v0.9.0`:

1. sync `main` and verify CI passes
2. deploy RC source once on HomeDocker and verify health/readiness/status
3. tag and publish `v0.9.0`
4. confirm the release workflow passes its exact-published-digest smoke test
5. pull the published GHCR `0.9.0` image on HomeDocker
6. recreate the service from the published image without rebuilding locally
7. verify the running image digest matches the pulled GHCR artifact
8. verify DB schema/profile/token persistence
9. restart once and verify readiness remains healthy
10. verify authoritative watched/watchlist counts remain populated
11. verify the known dual-IMDb regression remains clean
12. verify Strand native Trakt + AIOStreams coexistence remains duplicate-free
13. verify rollback to the v0.5.0 release image using the same schema-1 database

## v1.0 gate

v1.0 should be cut only after v0.9.0 completes a production burn-in with no watch-state, auth, release-artifact or recovery regression.
