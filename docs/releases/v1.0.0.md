# v1.0.0 — Stable release

Status: **stable release packaging / pending exact-published-digest HomeDocker canary**.

## What v1.0.0 means

v1.0.0 establishes HomeDocker Trakt Bridge as a stable self-hosted sync layer between AIOStreams watch state and Trakt.

The stable authority model is:

```text
Trakt        = canonical watched/resume history
Trakt Bridge = bidirectional sync and rate-limit/recovery layer
AIOStreams   = Jellyfin-compatible playback/state surface
AIOMetadata  = metadata/catalog + optional secondary-tracker fan-out
```

For clients that can also use native Trakt, the recommended Bridge mode remains:

```env
PULL_IDENTITY_MODE=trakt
```

## Production qualification

The v1.0 code line is promoted from the accepted v0.9.2 production candidate.

HomeDocker burn-in on the exact published v0.9.2 digest ran for 45.78 hours and ended with:

- healthy `/health` and `/readiness`
- DB schema `1`
- one connected Trakt profile with no reconnect requirement
- 134 successful pulls
- 73 authoritative pulls
- authoritative state still populated at 282 watched movies, 8478 watched episodes and 81 watchlist items
- 477/477 retained AIOStreams → Bridge deliveries in final `delivered` state
- zero current pending/non-final Bridge-sink deliveries
- dual-IMDb regression clean
- duplicate identity / duplicate Continue Watching symptom absent
- no required DB migration or cache purge
- idle CPU approximately 0% in the final samples

Trakt rate limiting did occur during extended use. v0.9.2/v1.0 behavior successfully contained it with shared profile cooldown, Retry-After handling, stale-safe reads and AIOStreams delivery retries.

## Freshness

Public defaults remain conservative:

```env
PULL_CACHE_TTL_SECONDS=300
PULL_HINT_SECONDS=300
PULL_STALE_IF_ERROR_SECONDS=3600
```

HomeDocker has separately qualified:

```env
PULL_CACHE_TTL_SECONDS=60
PULL_HINT_SECONDS=60
```

That lower profile is measured deployment-specific tuning, not the public default.

AIOStreams Watch State runtime settings remain at upstream defaults for the stable baseline.

## Known non-blocking observation

Some Trakt history entries may be counted twice when the upstream Jellyfin/AIOStreams path generates repeated semantic `played` marks for the same item at different timestamps.

The qualified HomeDocker topology ruled out AIOMetadata 3.3.2 as a Trakt watch-tracking writer. Bridge retry itself also does not duplicate the same event ID.

This behavior is tracked separately in issue #40 and is intentionally deferred beyond v1.0 so that a heuristic fix does not break legitimate rewatches.

## Release artifact acceptance

After tag `v1.0.0` is published, the release workflow must:

1. pass syntax checks and the complete automated test suite
2. build and push the public linux/amd64 GHCR image
3. publish SBOM and provenance metadata
4. smoke-test the exact published digest
5. verify application version and DB schema from the published artifact

HomeDocker must then run that exact digest and verify:

```text
v1.0.0 exact digest
  -> accepted v0.9.2 exact digest
  -> v1.0.0 exact digest
```

before the release gate is closed.

## Upgrade from v0.9.2

Back up:

- `bridge.db`
- `.env`
- Compose configuration
- reverse-proxy configuration

Then pull/recreate the v1.0.0 image without deleting the data volume.

No OAuth reconnect, DB migration or cache cleanup is expected.

After recreation, verify:

- `/health`
- `/readiness`
- connected profile state
- `PULL_IDENTITY_MODE=trakt`
- authoritative watched/watchlist sync
- running image tag/digest
- normal playback → Trakt delivery
