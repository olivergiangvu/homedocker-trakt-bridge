# G2-1B: StartIndex=0 first-page candidate — SHADOW AUDIT ONLY

## Grounded operator result (2026-10-18)

With real macOS Odin pilot and Draft #134 pinned SHA a4e855e5ea7c310e9a5f329f87f1f5871e4f3f27: NextUp=1, Resume=1, 6 AIO HTTP 2xx and zero AIO 4xx/5xx. Actual v1.4 Gateway Shadow GET finished 2xx after 1368ms (AIO NextUp 1306ms). No timeout, transport error or production write.

The sole excluding condition was an exact single StartIndex=0 query key; SeriesId, ParentId, other offsets and multiple restricted keys were zero. Previous Gateway design intentionally skipped user mapping and metadata at the StartIndex gate. This does not prove missing aliases or qualify any live deduplication.

## Why first-page output is not safe to mutate yet

The existing pure verified-alias filter sets TotalRecordCount to the filtered Items length. In a paginated request StartIndex=0, removing one entry could shift next-page offsets and make TotalRecordCount and Count misleading. Some AIO-compatible endpoints report only a fetched-prefix count, not the real library universe. Thus this Draft does NOT allow filtering Odin or direct Gateway clients.

## Strictly shadow-only candidate

1. Gateway option jellyfinGatewayFirstPageShadowAudit defaults false, and only the transient G2-1B HomeDocker runner enables it.
2. Only a *single* literal StartIndex=0, no SeriesId or ParentId and absent or one Limit of 1..50 can be evaluated. Duplicate StartIndex, StartIndex=00, nonzero offsets, scoped requests or invalid/oversized Limit still pass through without any extra user/metadata reads.
3. When qualified, use the existing authenticated /Users/Me same-user check, verified in-RAM graph and bounded series metadata, if and only if at least 2 Items with valid auth/aliases. A mismatch/uncertainty fails open.
4. The candidate filtered payload exists only in memory for numeric hypothetical counters; it is NEVER sent to Odin or even substituted into the actual Gateway HTTP response. Original AIO JSON, order, TotalRecordCount, Count, ETag and response headers remain intact.
5. Only fixed numeric counters are emitted: first_page_audit_attempts, first_page_audit_qualified, first_page_audit_would_normalize, first_page_audit_candidate_removed, first_page_audit_no_change, first_page_audit_errors. No auth, IDs, titles, progress, query values, paths or exceptions are captured or reported.
6. Still one short-lived loopback-only Gateway+ingress Node process, 3 max NextUp shadows, 25s deadline per attempt, 3m maximum process, no production RC6/SQLite/Trakt/nginx/Docker edits, playback or watched-state writes.

## Remaining qualification

Even a hypothetical alias 2-to-1 is NOT pagination-safe or an authorization for G2-1C. Before changing client response, need the actual pagination contract and proof that offsets, Count, TotalRecordCount, page order and Resume remain coherent across page 1 and subsequent pages. First-page metadata tests alone are not that proof.
