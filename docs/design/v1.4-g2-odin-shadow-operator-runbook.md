# G2-1B — HomeDocker operator shadow launcher (candidate, Draft only)

## Scope, confirmations and boundary

This PR introduces a **temporary** normal-user Node child runtime. It is not added to Docker Compose, systemd, Portainer, host nginx, Odin original server, or RC6. It makes no production SQLite writes, Trakt HTTP calls or playback/watch-history writes. All PRs remain Draft/unmerged and \`V140_STABLE_RELEASE_HOLD\` is mandatory.

The operator already confirmed **real Odin macOS** NextUp HTTP 200 and Resume 2xx via the previous isolated G2-1A observer. There have been *intermittent* AIO Items 5xx and two unclassified other 4xx, so the next traffic sample must not assume they are fixed.

### Read-only preflight (no listener, credential, auth POST)

Run only after checking this PR's full security review and CI, with an immutable commit pin. The Python launcher **requires sudo** only because production RC6 SQLite mount needs privileged read access; uses \`mode=ro/query_only\` and never imports graph into the DB. It validates running RC6 pinned image, AIO expected Docker topology and public health, **exact legacy scope 17 shows / one alias**, free host ports \`17431\` and \`17432\`, and Node 24+ available to the **original SSH operator**. The launcher searches that user's `$HOME/.nvm/versions/node/v24.x.y/bin/node` first, then the sudo PATH as a fallback. Every `node --version` check and live Node child runs with `SUDO_UID/SUDO_GID` privileges dropped **before** execution. `sudo` must not execute a binary controlled by the SSH user as root. Installing Node 24 with `nvm install 24` from the **normal user's SSH session**, without `sudo`, does not modify `/usr/bin/node`, existing Node 14 or Docker images. If not installed, FAIL CLOSED — do not substitute Docker \`--network host\` or new privileged daemon.

\`\`\`bash
sudo python3 -B scripts/audit-v140-g2-odin-shadow-host.py --mode preflight
\`\`\`

Expected only when evidence actually matches: \`SHADOW_PREFLIGHT_PASS_NO_LISTENER\`. Any \`G2_SHADOW_STOP_...\` must be diagnosed, not bypassed.

### Live shadow is separate, never automatic

**This is only an operator option after preflight and separate security acceptance.** The two explicit alternatives are:
- \`--mode login --confirm V140_G2_ODIN_SHADOW_ONE_CLIENT_ONE_LOGIN\` — one AIO \`AuthenticateByName\` POST with hidden UUID/alias and PIN entered into local SSH terminal, then authenticated GET \`/Users/Me\`.
- \`--mode existing-token --confirm V140_G2_ODIN_SHADOW_ONE_CLIENT_EXISTING_TOKEN\` — existing AIO token entered hidden only in local terminal, authenticated GET \`/Users/Me\` but no login POST.

The extra AIO login token from the parent is used **only** for the identity read, then deleted from the Python local variable. Neither password/PIN nor that token enters Node payload or file. Parent sudo Python reads one single RC6 profile's legacy identity-alias JSON via production SQLite read-only, validates 17/1 and sends the private profile, authenticated AIO User ID and legacy graph JSON to the child through **anonymous stdin RAM**. Child is dropped to \`SUDO_UID/SUDO_GID\` (must be nonroot) before starting Node, with scrubbed process environment and no argv credentials. Node performs **one in-memory** verified alias registry migration. The connected-profile marker is synthetic, not a copied OAuth secret. If exact graph validation fails, no listener starts.

Child creates the **actual v1.4 \`createJellyfinGateway()\`** bound to \`127.0.0.1:17432\` and an Odin shadow ingress \`127.0.0.1:17431\` as the **same OS user and same Node process**. Ingress holds trusted Gateway server object (not just a port) and only after bind prints \`G2_SHADOW_RUNTIME_READY_LOOPBACK_ONLY\`. The parent prints \`G2_ODIN_SHADOW_READY_LOOPBACK_ONLY\` once. No public listener.

On Mac, reuse the already-existing **AIO G2 Pilot** Jellyfin entry and SSH tunnel:
\`\`\`bash
ssh -N -o ExitOnForwardFailure=yes \
  -L 127.0.0.1:17431:127.0.0.1:17431 <existing-SSH-target>
\`\`\`
(Don't reproduce private target details or enter any password in chat.)

In Odin only visit Home/Continue Watching; do NOT Play, Mark Watched, Watchstate Sync, Trakt Sync, edit the ordinary AIO server, or switch a production user to pilot. AIO serves original NextUp/Resume and all other GET responses. At most three exact NextUp GETs are **also** sent to a same-process Gateway for *shadow measurement* with Odin's transient AIO auth headers. Gateway's outbound HTTP is allowlisted to GET \`/jellyfin/Shows/NextUp\`, \`/jellyfin/Users/Me\`, \`/jellyfin/Items/{SeriesId}\` on the fixed \`127.0.0.1:3240\` AIO. It cannot write SQLite, call Trakt or modify playback. Unknown or write HTTP methods are blocked at ingress; only exact AIO AuthenticateByName POST is permitted and size limited.

Pilot automatically times out and tears down after **3 minutes** or sooner using Ctrl+C at the parent HomeDocker terminal. Child shutdown closes both owned listeners; the parent prints only **strictly whitelisted anonymous metrics**. Any shadow failure/timeout never changes Odin responses. \`gateway_alias_removed_items\` may be 0 if no actual alias pair appears. Do not invent 2→1 on live media; synthetic proof remains separate.

### Exit and acceptance

All results say \`real_odin_gateway_client_qualified=false\`, \`shadow_canary_complete=false\`, \`filter_response_sent_to_odin=false\` and release HOLD. Those statuses remain until a human reviews live anonymized counters and client user experience; the program **must not self-certify**. It is only G2-1B shadow verification, not G2-1C NextUp cutover.

The code does not store JWT, AIO token, graph JSON, title/episode, raw paths, query values, passwords or UUIDs in logs. However, **the process RAM contains the AIO user and legacy profile data and transient request headers**; OS root/process debuggers could still access RAM, and this is a loopback service, not a separate cryptographic identity channel. Use SSH-tunnel only, keep the pilot brief, and stop if other users/processes unexpectedly appear or if API errors increase.

### Known limitation and follow-up

Host Node **24+ is required under the normal SSH operator**. On the observed host, the existing user `nvm` Node was 14.21.3 and sudo `/usr/bin/node` was 18.19.1, so the old preflight correctly returned `G2_SHADOW_STOP_HOST_NODE_24_REQUIRED`. The revised launcher discovers a user-scoped `nvm` Node 24 but launches its `--version` check **after dropping sudo privileges**; it never upgrades or replaces the system binary. A missing Node executable, changed RC6/AIO topology, altered show/alias count, occupied preview port, or inaccessible SQLite must stop. Do not attempt to download Node as root or publish 17431/17432 to the LAN to work around preflight. The current parent launcher returns aggregate-only counters; a separate operator checkpoint assesses \`shadow_attempted>0\`, \`shadow_completed>0\`, all requests GET except bounded AIO login, no shadow errors, zero production/Trakt writes, no unexpected 5xx and unchanged Odin client rendering. These are not automatically granted by code.

No host command to launch live mode should be executed before **a successful preflight and explicit operator review**.
