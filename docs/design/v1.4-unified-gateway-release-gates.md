# v1.4.0 — Unified Gateway release decision and production qualification gates

**Decision date:** 2026-10-16. **Target release:** `v1.4.0`, not a repackaged `v1.3.0`. **Status:** DEVELOPMENT / NOT RELEASE-QUALIFIED / NO HOME-DOCKER APPLY.

## Distinguish stable history, on-host state and next release

- `v1.3.0` was already published on 2026-10-14 at tag commit `8c505089e0c5ad2e7ce1514bd9c1acf1722bea95`; published manifest-list digest is `sha256:b15e31895eef825f55f33ada6fa3066747a6f954fbdf4acedb7a083615126f37`. Do not retag that release to pretend a Gateway upgrade shipped.
- The most recent independently observed HomeDocker Bridge release in this project is `v1.3.0-rc.6`, protected and pinned. A later host deployment must be verified from actual host output; publication, GitHub CI and README edits are NOT deployment evidence.
- Root-owned Docker volume preflight returned `[Errno 13] Permission denied` on `/var/lib/docker/volumes/homedocker-trakt-bridge_trakt_bridge_data/_data` during an unprivileged `Path.is_dir()` check. GitHub PR #99 (merged to main as `a86e6e60b4f154424be01861bf27ff032a510d46`) fixes that **read-only inspection** via privileged stat of the exact mounted directory and regular `bridge.db`, not by chmod/chown. The original aborted preflight had no `--apply`; there was no production rollout.
- PR #95 is still Draft, based on `fix/r23d2b1c-verify-existing-entrypoint` rather than current main. Its Gateway code, tests, safety design and release documentation **must be reconciled with current v1.3 main** before any merge; changing the base is a separately audited action.

## What `Unified Gateway` means in v1.4

One **HomeDocker Trakt Bridge product** with one canonical Trakt authority, one profile-scoped verified identity graph and one dashboard. An opt-in Jellyfin-compatible Gateway module normalizes only the sufficiently verified NextUp alias mapping. AIOStreams continues as an upstream component and may roll independently; Remux, Trellis, Strand and native Trakt clients retain existing read/playback behavior. No second permanent metadata authority, Trakt writer or watch-history sync loop may be introduced.

**Source reality:** `src/index.mjs` on the draft branch already wires `createJellyfinGateway()` when `JELLYFIN_GATEWAY_ENABLED=true` and keeps it disabled by default; `src/gateway-dashboard.mjs` reports an explicitly non-production-qualified listener/identity view. `src/gateway-standalone.mjs` and `Dockerfile.gateway-canary` are an **isolated, credential-free proof process**, not a final permanent second production Bridge. Bridge image `package.json` and `src/config.mjs` remain `1.3.0` in the Draft branch. No `v1.4.0` stable tag or qualified unified image exists.

**Go/No-Go:** Every gate above is mandatory. Any NOT INSTALLED, NOT TESTED, or unverified item means `V140_STABLE_RELEASE_HOLD`. Passing tests on a GitHub runner alone is insufficient. In particular, never infer kernel traffic isolation from source-only attesters, and never turn an all-absent inventory into permission to create a canary.

## Execution sequence / release boundaries

1. Keep published `v1.3.0` tag and image immutable; close the mistaken v1.3 deployment request. Restore no DB/Compose files because no deployment took place.
2. Keep PR #95 as development; reconcile exact current `main` changes (#92, #96–#99) before stable merge. Preserve RC6 immutable fallback and R23A/R23B archive.
3. Finish independent guarded boot/total-fence-loss/Docker-daemon-restart tests on **disposable runner/VM**. No privileged firewall/port/network experiments on HomeDocker before separately approved host controls.
4. Validate unified Gateway code as **one Bridge service** and document whether temporary gateway-only proof container is deleted after an owned test, with exact ownership. Do not leave a second permanent Gateway product or independent dashboard.
5. Obtain intentional HomeDocker synthetic canary approval only after live host preflight and independent evidence prove fail-closed boot/kill boundaries. Authenticated AIO/Jellyfin routes must remain disabled until separate permission and qualification.
6. Qualify `v1.4.0-rc.1` with same-DB/Trakt semantics and actual clients; establish rollback, event/429, near-terminal playback and duplicate NextUp evidence.
7. Only then consider a stable `v1.4.0` tag at an exact reviewed commit and GHCR digest, followed by **Bridge-only** deployment with SQLite online backup and immutable rollback. Publish/deploy are distinct checkpoints.

**Absolute prohibitions while HOLD:** no `v1.4.0` stable tag, no GHCR `:latest` re-tag as an unqualified gateway, no Portainer bulk redeploy, no AIOStreams pin/restart, no Trakt history sync/cleanup or direct SQLite mutation, and no nft/iptables changes on the protected host.
