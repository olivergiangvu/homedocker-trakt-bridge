# G2-1B — Odin macOS gateway **shadow** pilot contract (design only)

## Inputs confirmed, not inferred

Operator pilot used **Odin native macOS** against AIOStreams' own Jellyfin-compatible server `/jellyfin`, through one separate Odin AIO G2 Pilot server entry and an SSH-tunneled, unprivileged, ephemeral observer.

Latest G2-1A HomeDocker PR #128 (SHA `75f7826605750a3f5e743f928ad5469f922504e7`): **9 requests; 1 NextUp HTTP 200; 1 Resume HTTP 2xx; Other = 5×2xx and 2×4xx; 0×5xx.** Observer removed, zero AIO playback writes forwarded, zero SQLite writes, zero production nginx reload, zero Gateway forwarded requests. Earlier PR #127 sample had **2×5xx under Items**; no corresponding errors repeated in the most recent sample. **Do not assert they are fixed.** Two `jellyfin_other` 4xx remain unattributed; do not treat them as silently resolved.

G1C already proved an actual v1.4 Gateway can GET AIO NextUp and 20 metadata requests via an authenticated AIO session with an in-memory 17-show/1-alias graph, and G1B exercised **synthetic** 2→1 alias filtering. Neither has yet proven *Odin-originated* Gateway traffic or naturally occurring live duplicate suppression.

## Why G2-1B should begin as a no-impact shadow

A direct full-server switch to the standalone NextUp-only Gateway would break Odin's login, library, artwork, streaming and playback paths. A direct **intercept** of the NextUp response is also unnecessary as the first step: the client path, headers, profile/user mapping, latency and fail-open properties can first be tested by a shadow.

| Route received by a **dedicated pilot-only ingress** | Served to Odin | Shadow traffic |
| --- | --- | --- |
| Exact `GET /jellyfin/Shows/NextUp`, original query unchanged | Existing AIO, byte-for-byte | *One bounded, best-effort GET copy* sent to Gateway **only if explicitly enabled** |
| `GET /jellyfin/UserItems/Resume`, legacy Resume | Existing AIO | None |
| Auth login POST | Existing AIO, allowed only on exact `/jellyfin/Users/AuthenticateByName` | None |
| Other GET/HEAD/OPTIONS | Existing AIO | None |
| Playback/mark watched/sync or any non-read method other than the exact login POST | Locally denied (405) | None |

**Critical:** shadow failures must not change client responses, timeout the original AIO request, leak OAuth/Jellyfin tokens in logs or authorize client-response interception. Do not enable Odin's optional separate Trakt sync during this read-only pilot, since Trakt Bridge already owns scrobbling.

The host implementation is **NOT** in this PR. `src/odin-g2-shadow-policy.mjs` is a pure, no-network/no-listener/no-container helper, and `test/practical-g2-odin-shadow-policy.test.mjs` tests route flags only. It does not deploy, run, publish, or authorize a real shadow. A later implementation will require specific source review for host bridging and strict session/header handling before accepting operator credentials.

## Route and rollout constraints for the proposed implementation

1. One **existing** dedicated Odin pilot entry only, via Mac SSH `-L 127.0.0.1:17431:127.0.0.1:17431`. Keep the normal AIO entry and existing production URL unchanged.
2. New, separately approved loopback-only ingress `127.0.0.1:17431` and candidate Gateway `127.0.0.1:17432` would be temporary and auto-cleaned. Ports must be checked again immediately before use; previous G2-0 preflight only observed them unbound at an earlier time.
3. Candidate Gateway may use **only in-memory aliases** imported from the one connected profile's verified legacy cache, alongside a confirmed AIO UserID matching the operator-attested profile. It must not mount production DB RW, create another Trakt writer or receive Bridge Trakt/OAuth secrets. Preserve the G0/G1 one-Bridge integration design; shadow is an *ephemeral test harness*, not a second permanent Gateway product.
4. If using Odin's own AIO bearer token on a shadow GET, it may reside temporarily in RAM in a trusted candidate network process and must be forwarded only to the fixed existing AIO loopback endpoint. No credential in argv/env, temporary disk, proxy logs or GitHub. User should explicitly approve this boundary before live execution.
5. Avoid `docker --network host` or other broadened access until a separate security and rollback review; prefer a non-root local process if runtime Node is available. A Docker alternative must be specifically reviewed, not assumed equivalent to isolation.
6. Sample aggregate counters: `client_nextup_200`, `gateway_shadow_nextUpRequests`, `shadow_upstream_status_groups`, `shadow_failed_open`, `shadow_response_changed`, `gateway_metrics_nextUpRemovedItems`, `resume_passthrough`, `other_4xx/5xx`; never raw URL, query, user ID, IMDb ID, session headers or title.
7. **G2-1B shadow PASS** would mean an Odin NextUp request was served unchanged from AIO and a copy reached the actual Gateway, preserving the correct user/profile, zero writes and bounded latency. **It is NOT NextUp filtering acceptance**, as Odin still receives original AIO response. A separately approved subsequent G2-1C could test the actual filtered response only after shadow integrity passes.
8. Stop immediately on NextUp/Resume 4xx/5xx, incorrect same-user mapping, shadow request leakage, unacceptable latency or AIO/other API degradation. Roll back by closing only the pilot tunnel and ephemeral ingress/Gateway process. Do not reload host nginx or restart RC6/AIO. Verify the normal Odin AIO entry still works.

## Gate semantics

The new read-only evaluator `assessOdinShadowReadiness()` accepts the latest anonymous G2-1A report as a **design gate** only: `SHADOW_DESIGN_GATES_MET_NOT_DEPLOY_AUTHORIZED`. It explicitly retains `other_4xx_still_unexplained=true`, `historical_items_5xx_resolved=false`, `shadow_pilot_started=false`, `actual_gateway_client_qualified=false` and `stable_release_hold=true`.

It refuses partial/contradictory counters, active prior observer, any NextUp or Resume 4xx/5xx, any Other 5xx in the current sample, unexpected playback writes, production SQLite changes, nginx reload or a false positive already-qualified-Gateway claim. Requiring success in a *single* latest sample is not evidence prior intermittent failures have been fixed.

**Current decision:** proceed with the G2-1B shadow design and isolated integration tests, not with live client interception or release. `V140_STABLE_RELEASE_HOLD` remains. No production edits/merges/tags without a distinct later approval.
