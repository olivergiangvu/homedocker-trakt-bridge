**As of 2026-10-13:** RC6 (`1.3.0-rc.6`) is the running HomeDocker production baseline, pinned by immutable GHCR digest. **Do not promote v1.3 Stable on diagnostic tests alone.** No AIOStreams source/image modification. No restore/replay, bulk Trakt cleanup, or automatic history rewrites.

## Confirmed: single-show double Continue Watching remediation

*Ok! Let's Get Divorced* had one Trakt canonical history under `tt44051354` and eight local episodes under AIO IMDb `tt44094505` with `tmdb:276470` video IDs. Distinct `series_key` groups contained 18 episodes without `match_key`. AIO `NextUp` returned Trakt S01E10 (active resume) plus stale AIO S01E09.

Operator confirmed **all affected clients no longer show double CW cards** after a one-time `dropped` preference on the obsolete AIO series via its supported Jellyfin API. This is an operationally **resolved issue**, not proof that cross-provider `match_key` mapping has been repaired permanently. AIO may undrop after local playback under the obsolete series. Never automatically reapply `dropped` without fresh proof.

## Delivered Phase C: non-mutating Identity Drift Monitor

`scripts/monitor-identity-drift.py` reads AIO and Bridge SQLite with `mode=ro` and `PRAGMA query_only=ON`. It inspects **only one exact active AIO watch sink and one connected Bridge profile**. It loads learned exact IMDb alias pairs from the Bridge cache and the known immutable show-ID fixture. No title matching, Trakt/Jellyfin HTTP, DB writes, or authentication material printed.

Crucially it groups watch-state episodes by `series_key` (not an `item_key LIKE e|tt...` pattern). It checks whether the current stale-series drop is *effective* under AIO's `dropped_at > latest played-sort_at` rule. Each pair is classified:

| Status | Meaning |
| --- | --- |
| `MITIGATED_BY_DROP` | Two episode timelines still exist, but the stale alias drop is newer than that alias's latest active playback |
| `SPLIT_TIMELINE_RISK` | Two series histories remain and no effective stale drop exists; a double card may recur |
| `DUAL_RESUME_REVIEW` | Both aliases have an unfinished resume; never pick one automatically |
| `SINGLE_TIMELINE` | Only one of the two ID spellings currently has episodes |
| `NO_EPISODE_EVIDENCE` | Neither side has local history for this mapping |

The monitor does not claim to prove what a client rendered. It deliberately **cannot fix the issue itself** and has no retry/repair feature. It only reports a drift risk; repairing again requires fresh API and 18-row verification.

### Run once on the HomeDocker SSH host (read-only)

```bash
sudo python3 ~/monitor-identity-drift.py --json
```

Optional machine-readable alert mode returns exit code `3` when a risky split exists:

```bash
sudo python3 ~/monitor-identity-drift.py --json --fail-on-drift
```

Exit `0` means no **observed** risky split among verified pairs; it is not a complete NextUp client-level guarantee. A hard SQL/scope/alias schema failure exits nonzero with `STOP`. Do not publish raw Bridge database files.

No background service/timer is installed by this PR. A future opt-in systemd timer may run this read-only script; it must not reissue `dropped` actions automatically.

## Read-only RC-to-Stable Event Pulse (429 / 422 / compare / canonical)

`scripts/audit-stable-event-pulse.py` reads only the **current connected Bridge profile's locally retained `event_log`** with SQLite `mode=ro` and `query_only=ON`. It summarizes an observation window without printing OAuth secrets, profile IDs, event IDs, titles, or raw event details.

```bash
sudo python3 ~/audit-stable-event-pulse.py --hours 24
```

Outputs bounded counts for `pull_ok`, `pull_cached`, `pull_stale`, `pull_error`, `event_errors`, `explicit_rate_limit_signals`, `terminal_ignored`, `explicit_terminal_422_errors`, `canonical_verifications`, and `compare_terminal` / `compare_decisions`. Also flags any compare-only log lacking `writesTrakt=false`.

**Limitations:** Bridge retains at most 1,000 recent event rows. Counts cannot establish a full 24h soak if historical rows have been pruned. A native-Trakt client bypasses Bridge and cannot be counted here. Not all upstream rate limits contain an explicit HTTP 429; `explicit_rate_limit_signals=0` does not prove none occurred. Absence of near-terminal ignored events means the boundary has **not necessarily been exercised**. Compare-only counters are zero until the opt-in mode is explicitly qualified.

Both monitor scripts operate without passwords, API keys, services, or network calls. Neither is enabled as an automatic timer, neither can fix history or resync Trakt, and neither changes production just by running.

### Independent image policies and rolling-upstream compatibility (observation only)

Run `scripts/audit-runtime-image-provenance.sh` to capture the *current* running image IDs, creation times, configured references and local `RepoDigests` for troubleshooting/rollback records. It is informational only and performs **no pulls, image updates, secrets inspection, restarts or Compose writes**. It is NOT a gate that demands an immutable AIO image reference.

**Architecture policy:**

- **Bridge:** version independently and pin an immutable, qualified **Bridge** image digest, with a tested downgrade path.
- **AIOStreams:** intentionally stay on `ghcr.io/viren070/aiostreams:latest`; do **not** pin its Compose reference to a digest and do **not** require a particular AIO digest to qualify Bridge Stable.
- **Integration:** enforce a behavioral compatibility contract across AIO upgrades: Bridge health/readiness, connected exact sink/delivery health, AIO watch-state pull/push and Jellyfin Resume/NextUp semantics, maintained canonical watched/resume/NextUp state and identity drift, no unexpected Trakt writeback/429 amplification. AIO is a **rolling upstream dependency**.
- **Rollback:** retain the *previous running AIO image ID/digest as a recovery artifact*, together with Compose/env backups and restored-volume considerations; this is not a permanent pin. A `docker compose pull` may legitimately change `latest`, so test after update and keep the previous image available to restore if a regression is found.
- **Fail-safe:** if a new AIO revision changes the Jellyfin/watch-state contract, Bridge must surface incompatibility, not corrupt watched history or force speculative writes. Support a temporary AIO rollback only when needed, then resume `latest` once compatibility is restored.

**Do not conflate recording an immutable rollback artifact with pinning AIOStreams in production.** Never assert an image digest is current merely because it appeared in an earlier investigation.

## Rolling AIOStreams compatibility contract — required, not version pinning

AIOStreams is intentionally **upstream-owned and independently updated via `latest`**. The release is qualified against a contract, **not a frozen AIO build**.

| Trigger | Non-destructive compatibility check | Acceptance |
| --- | --- | --- |
| Any AIOStreams `latest` update | Capture old/new running image IDs; check AIO container healthy and Bridge `/health` + `/readiness` | The upgraded AIO and unchanged Bridge both healthy |
| AIO integration after update | Confirm exact connected Bridge watch sink, `pending=0` when settled, and normal pull/push events | No prolonged failed/pending delivery, no unexpected credential or schema errors |
| Jellyfin-compatible Continue Watching | Verify `/UserItems/Resume` and `/Shows/NextUp` using normal authorized client or bounded authenticated GET | Resume point preserved; no duplicate card from the documented dual-IMDb fixture |
| Native Trakt coexistence | Confirm Trakt canonical identity, unchanged watch-state semantics and `compare` mode remains non-writing | No new duplicate history or false watched/unwatched fan-out |
| Drift monitor | Read-only `monitor-identity-drift.py` | Existing `dropped` mitigation remains effective, or an observed regression is investigated before action |
| Rollback contingency | Retain previous AIO image, Compose/config snapshot and volume backup plan | Independent revert possible *if needed*, without permanently binding Bridge Stable to old AIO |

Automating checks or notifications on update is allowed; automatically modifying AIO history, running a second `dropped` action, rewinding Trakt, or upgrading Bridge implicitly is **not**. Bridge version stability must not delay ordinary AIO upstream upgrades.
