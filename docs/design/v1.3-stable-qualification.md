**As of 2026-10-13:** RC6 (`1.3.0-rc.6`) is the running HomeDocker production baseline, pinned by immutable GHCR digest. **Do not promote v1.3 Stable on diagnostic tests alone.** No AIOStreams source/image modification. No restore/replay, bulk Trakt cleanup, or automatic history rewrites.

## Confirmed: single-show double Continue Watching remediation

*Ok! Let's Get Divorced* had one Trakt canonical history under `tt44051354` and eight local episodes under AIO IMDb `tt44094505` with `tmdb:276470` video IDs. Distinct `series_key` groups contained 18 episodes without `match_key`. AIO `NextUp` returned Trakt S01E10 (active resume) plus stale AIO S01E09.

Operator confirmed **all affected clients no longer show double CW cards** after a one-time `dropped` preference on the obsolete AIO series via its supported Jellyfin API. Pre- and post-checks confirmed canonical S01E10 and all 18 episode records intact. See diagnostic #83 and HomeDocker-side fix #85. Experimental upstream-edit PR #84 was closed **without merge**.

This is an operationally **resolved issue**, not proof that cross-provider `match_key` mapping has been repaired permanently. AIO may undrop after local playback under the obsolete series. Never automatically reapply `dropped` without fresh proof.

## Delivered Phase C: non-mutating Identity Drift Monitor

`scripts/monitor-identity-drift.py` reads AIO and Bridge SQLite with `mode=ro` and `PRAGMA query_only=ON`. It inspects **only one exact active AIO watch sink and one connected Bridge profile**. It loads learned exact IMDb alias pairs from the Bridge cache and the known immutable show-ID fixture. No title matching, Trakt/Jellyfin HTTP, DB writes, or authentication material printed.

Crucially it groups watch-state episodes by `series_key` (not an `item_key LIKE e|tt...` pattern). It checks whether the current stale-series drop is *effective* under AIO's `dropped_at > latest played-sort_at` rule. Each pair is classified:

| Status | Meaning |
| --- | --- |
| `MITIGATED_BY_DROP` | Two episode timelines still exist, but the stale alias drop is newer than that alias's latest active playback |
| `SPLIT_TIMELINE_RISK` | Two series histories remain and no effective stale drop exists; a double card may recur |
| `DUAL_RESUME_REVIEW` | Both aliases have an unfinished resume; never pick one automatically |
| `SINGLE_TIMELINE` | Only one of the two ID spellings currently has episodes |
| `NO_EPISODE_EVIDENCE` | Neither side has local history for this mapping |

The monitor does not claim to prove what a client rendered. It deliberately **cannot fix the issue itself** and has no retry/repair feature. It only reports a drift risk; repairing again requires fresh API and 18-row verification.

### Run once on the HomeDocker SSH host (read-only)

```bash
sudo python3 ~/monitor-identity-drift.py --json
```

Optional machine-readable alert mode returns exit code `3` when a risky split exists:

```bash
sudo python3 ~/monitor-identity-drift.py --json --fail-on-drift
```

Exit `0` means no **observed** risky split among verified pairs; it is not a complete NextUp client-level guarantee. A hard SQL/scope/alias schema failure exits nonzero with `STOP`. Do not publish raw Bridge database files.

No background service/timer is installed by this PR. A future opt-in systemd timer may run this read-only script; it must not reissue `dropped` actions automatically.

## Read-only RC-to-Stable Event Pulse (429 / 422 / compare / canonical)

`scripts/audit-stable-event-pulse.py` reads only the **current connected Bridge profile's locally retained `event_log`** with SQLite `mode=ro` and `query_only=ON`. It summarizes an observation window without printing OAuth secrets, profile IDs, event IDs, titles, or raw event details.

```bash
sudo python3 ~/audit-stable-event-pulse.py --hours 24
```

Outputs bounded counts for `pull_ok`, `pull_cached`, `pull_stale`, `pull_error`, `event_errors`, `explicit_rate_limit_signals`, `terminal_ignored`, `explicit_terminal_422_errors`, `canonical_verifications`, and `compare_terminal` / `compare_decisions`. Also flags any compare-only log lacking `writesTrakt=false`.

**Limitations:** Bridge retains at most 1,000 recent event rows. Counts cannot establish a full 24h soak if historical rows have been pruned. A native-Trakt client bypasses Bridge and cannot be counted here. Not all upstream rate limits contain an explicit HTTP 429; `explicit_rate_limit_signals=0` does not prove none occurred. Absence of near-terminal ignored events means the boundary has **not necessarily been exercised**. Compare-only counters are zero until the opt-in mode is explicitly qualified.

Both monitor scripts operate without passwords, API keys, services, or network calls. Neither is enabled as an automatic timer, neither can fix history or resync Trakt, and neither changes production just by running.

## HomeDocker first live qualification — 2026-10-13

Observed from owner's on-host read-only output (RC6 running image `1.3.0-rc.6`):

| Signal | Observed value | Gate |
| --- | --- | --- |
| `/health` | `status=ok`, version `1.3.0-rc.6` | PASS at sample time |
| `/readiness` | `ready=true`, DB OK, schema 1/1, one connected profile | PASS at sample time |
| Identity drift | 1 known learned pair, `MITIGATED_BY_DROP`, `attention=0` | PASS (at sample time) |
| History | 8 local AIO watched alias rows, 10 Trakt canonical rows (9 watched, S01E10 resume), zero mapped | Expected historical split; drop is effective |
| 24h Bridge pulse | 313 retained events in requested window, 189 playback, 106 `pull_ok`, 2 `pull_stale` | Observed evidence; not a full soak |
| Compare-only | 8 settled decisions: 3 `trakt_same_or_newer`, 5 `trakt_stale_candidate` | **Investigate five stale candidates; no writeback permission** |
| Global retention | 1,000 event rows retained | Previous v1 pulse signalled possible truncation **unconditionally**. Corrected v2 now reports oldest retained global timestamp and whether the *requested window* crosses the retention boundary. Re-run required. |
| Explicit 429/422 | No such counts in emitted output | **Not proof of zero errors**; event details may omit standardized status; other clients bypass Bridge |

The 5 stale comparison candidates only mean that, for matched item/episode, Trakt's paused timestamp and derived playback progress were older and behind the settled AIO candidate at comparison time. They do **not** prove Trakt watched/history is missing or that sending a resume/scrobble write is safe. Native-Trakt recency, intentional seek/rewatch, canonical watched history and exact matching still need separate evidence.

**Operational decision:** keep RC6 and exact AIO configuration; run read-only v2 pulse to verify whether the 24h window is covered by retained events and inspect aggregated decision reasons/gaps. Do not enable Trakt recovery writes based on these eight observations.

## Outstanding stable gates — do not silently enable feature flags

| Gate | Already in code / previous evidence | Remaining production qualification |
| --- | --- | --- |
| **Identity** | B8 RCA; user confirms CW repaired across all clients | Monitor shows `MITIGATED_BY_DROP` or other grounded non-risk; verify after normal playback under both clients |
| **AIO reconciler compare-only** (#70) | `AIO_RECONCILER_MODE=compare`, no writeback; restart-safe compare queue; native Trakt precedence with GET read lane | Stage compare-only separately, review read requests/429 and terminal classification samples, restart persistence, no Trakt POST/DELETE |
| **Duplicate history** | RC4/RC5 history-lineage and canonical snapshot guard | Distinguish intentional rewatches from native-Trakt double-writers using timestamp/source/session evidence; never blanket-delete history |
| **Terminal playback** | RC6 blocks Trakt pause 422 near terminal ≥99% without converting to watched | Obtain real complete/99% boundary case from live clients; confirm 90% completion rule and absence of false `history:add` |
| **Trakt rate limits** | RC6 ManagedTraktClient pacing and shared/read cooldown; authenticated 429 stale-cache fallback | Measure new 429, Retry-After, retries and GET amplification during soak; do not enable on-demand canonical verifier just to reduce stale dashboard percentages |
| **Canonical freshness** | `CANONICAL_ON_DEMAND_VERIFY=false` is default, opt-in single-flight with 120s minimum verify | Qualify separately against native Trakt marks and read 429; avoid write suppression on stale evidence |
| **Release engineering** | Node/Python tests, Docker build, image budget, Compose and health/readiness CI | Stage immutable candidate image, 24–72h supervised soak (window must be recorded), backup/recovery rehearsal, post-restart exact digest verification and rollback readiness |

### Do not change these production invariants

```env
PULL_IDENTITY_MODE=trakt
CANONICAL_ON_DEMAND_VERIFY=false
```

Keep the existing stable 90% completion semantics, pinned Bridge RC6 image, AIO production image, nginx host proxy, Docker volume mount layout, and exact Bridge sink identity. Never make `AIO_RECONCILER_MODE=compare` or writeback automatic merely because CI passed. No source changes or image rebuild to AIOStreams.
