## Runtime candidate in this PR

`src/odin-g2-shadow-ingress.mjs` exports only **`createOdinShadowIngress()`**. Importing does nothing: no bind, no environment, no disk/SQLite, no outbound HTTP, no Trakt, no credentials. The host runner is **not** implemented or deployed. The factory requires two explicit `http://127.0.0.1:<port>` endpoints and enforces a separate bind to **127.0.0.1 only**; no reverse proxy or production nginx adjustments. Test code creates local ephemeral mock AIO and mock Gateway on loopback, never contacts real services.

| Odin pilot HTTP route | Odin response | Shadow copy |
|---|---|---|
| Exact GET `/jellyfin/Shows/NextUp?...` | AIO response, streamed without decompression/mutation | **OFF by default**; if `shadowApproved`, best-effort copy to a separate local Gateway `GET /Shows/NextUp?...` |
| Resume GET, user-data GET, library/Items/Images/System GET, HEAD, OPTIONS | AIO only | No |
| Exact login POST `/jellyfin/Users/AuthenticateByName` | AIO only, bounded 256KiB in RAM | No |
| Watched-state, playback, other write method | 405, not forwarded | No |
| Non-Jellyfin URL, encoded slashes or invalid request target | 400, not forwarded | No |

- Shadow HTTP uses the original client Jellyfin authorization headers **only in memory** and **only** to the configured loopback Gateway. It does not use Bridge Trakt OAuth or secondary accounts. No headers, query, tokens or media IDs in metrics; only aggregate numeric counters. **Before any live run, verify that the target listener is the intended Gateway instance and the current Odin account maps to the one and only verified Bridge profile**, or a malicious/conflicting local listener might receive sensitive AIO auth headers.
- Shadow is **not** awaited by the AIO client response path. Its status/body NEVER supplies Odin's response. On shadow timeout, 4xx, 5xx, 2MiB cap or connection error, only aggregate counters change; client still receives AIO bytes. At most **three** attempted shadow GETs and **one** concurrent, 500–8000ms configurable shadow timeout. No serialized request-body/auth capture.
- AIO remains the original server under `/jellyfin`; shadow Gateway accepts unprefixed `/Shows/NextUp`. All route query values are **transient** (network only) and are not logged. An explicit query token inhibits shadow, but the original request stays direct AIO (pilot-specific).
- Logless, 15s AIO-proxy request timeout; AIO transport failure returns local 502. Client may still see AIO's legitimate existing 4xx or 5xx. This is **not** a fix for those upstream API errors.
- The current runtime is a standalone pilot harness, not a replacement for the integrated Bridge Gateway service. The live host runner and secure in-process actual v1.4 Gateway linkage still need separate design/approval; mock Gateway E2E PASS does not mean real Gateway or Odin acceptance.
