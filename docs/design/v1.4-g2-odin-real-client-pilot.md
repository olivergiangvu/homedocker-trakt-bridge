# G2-1 Odin — API discovery and isolated client pilot design (NO host apply)

## Decision and evidence

Operator explicitly selected **Odin** as the first G2 real-client pilot, instead of AIOStreams Desktop. Existing HomeDocker G2-0 preflight PASS at `0dd0406b1fc9ce3d29f4dbfaa2539fd55627dc85`: RC6+ AIO topology verified, Bridge 17 shows/1 verified alias group, proposed loopback 17431/17432 unbound *at check time*, no nginx/Docker/client/SQLite changes.

**External published facts (verified 2026-10-17):**
- Official [Odin website](https://odinapp.dev/) lists iPhone, iPad, Apple TV, and Mac native clients; personalized Continue Watching and profiles. This is a **Jellyfin-capable** native player, but the vendor public website does not publish the concrete Continue Watching HTTP paths.
- Official [Odin privacy statement](https://odinapp.dev/privacy.html) states Odin talks to operator-controlled Jellyfin/WebDAV servers, stores its own library index, watch history, Continue Watching and per-user profiles locally, can report progress to the server and may separately sync to Trakt/AniList if enabled. Thus **a visible Odin Continue Watching shelf is not evidence of `GET /Shows/NextUp`**; the shelf could use local cache or a Jellyfin Resume/UserData endpoint.
- [ElfHosted client compatibility guide](https://docs.elfhosted.com/guides/media/aiostreams-jellyfin/) describes testing/tuning Odin against Jellyfin-compatible addon-backed servers, but does not establish Odin's exact NextUp API path on **this specific build and HomeDocker**.
- Jellyfin SDK [`ShowApiGetNextUpRequest`](https://typescript-sdk.jellyfin.org/interfaces/generated-client.ShowApiGetNextUpRequest.html) documents that `GET /Shows/NextUp` exists. **API existence does not prove Odin calls it.**

## G2-1A: prepare accurate route discovery; observe first

New `src/odin-pilot-route.mjs` is a **pure, no-listener/no-network** contract that recognizes several *possible* API families; it never asserts Odin uses them. The default mode `observe` categorizes and forwards **everything to AIO**, including `GET /jellyfin/Shows/NextUp`. No candidate Gateway interception yet. It stores only aggregate counts in an in-memory counter object, never URI, query, user IDs, profiles, IMDb IDs, titles, authorization headers, cookies, payloads or watch positions. All tests are synthetic.

| Observed exact requests from **Odin pilot entry** | Discovery result / next decision |
| --- | --- |
| `GET /jellyfin/Shows/NextUp?... ` | Candidate for G2-1B interception; MUST prove method/path on-device |
| `GET /jellyfin/UserItems/Resume` or `GET /jellyfin/Users/{id}/Items/Resume` | Odin uses Resume; v1.4 NextUp filter cannot fix this card collection; do NOT claim NextUp success |
| `GET /jellyfin/Users/{id}/Items` and related UserData | May be separate personalized query, **needs payload-free route tracing before deciding any future support** |
| `GET /jellyfin/Users/Me`, authentication POST | Remain AIO; never Gateway |
| Playback/session POST requests | Remain AIO; **do not press Play during initial discovery** |
| `/jellyfin/u/{alias}` or other prefix | Upstream may use a configured AIO user-sharing route; do not rewrite or capture raw alias, STOP for contract review |
| No matching HTTP calls while client displays shelf | Odin likely cached data or another source; record `CLIENT_ROUTE_NOT_OBSERVED`; do not invent a Gateway PASS |

**Important:** Odin's privacy policy documents a local Continue Watching cache and an optional independent Trakt/AniList connection. First read-only stage uses only home-screen navigation, not playback, mark-watched, manual sync, logout or reconnect of existing client. Any subsequent playback test must separately review whether Odin's own Trakt sync would duplicate Bridge scrobbles.

## G2-1B proposed preview-only architecture (DESIGN, not installed)

The previously discussed preview-only scheme remains. Ports are proposed, **not reserved**:
- Existing unchanged AIO: `127.0.0.1:3240` on HomeDocker, externally published through existing nginx/reverse proxy as before.
- Proposed **new** isolated preview ingress: host loopback `127.0.0.1:17431`.
- Proposed temporary v1.4 Gateway: host loopback `127.0.0.1:17432`, with explicit one-user↔Trakt profile configuration and a copied **in-memory or disposable** identity graph. Never mount production database read/write or import aliases there.
- Odin on **Mac** could use a dedicated local `ssh -L` tunnel and *separately added* preview server entry. Actual Mac/tvOS/iOS device has **not yet been selected**. An Apple TV **cannot use a tunnel that listens only on the Mac's 127.0.0.1**; tvOS requires an explicitly reviewed LAN-only or private HTTPS preview endpoint. **Do not open WAN forwarding, DDNS or current AIO vhost.**
- Preview ingress must send *all* auth, library, playback, images, websocket and non-NextUp requests to **existing AIO**, with original method, headers, cookies, body and query, preserving response semantics and secure streaming. It must not store access tokens or forward unrelated APIs to Gateway.
- Only **after an Odin NextUp GET is really observed**, a separately approved `intercept` mode may route **exact `GET /jellyfin/Shows/NextUp`** to temporary Gateway `/Shows/NextUp`; everything else remains on AIO. Query string remains exact and unchanged.
- Preview-only ingress counters must distinguish `observed_nextup`, `forwarded_gateway`, `gateway_nextUpRequests`, `gateway_unchangedResponses`, `gateway_removedItems` and HTTP errors; no raw access_log or user identifier, since even a query string can contain `UserId` or secrets. Static `/health` alone is not enough for route acceptance.
- **The route classifier added here is only a spec and test target, not a proxy or nginx config.** No host services have been deployed.

```text
Odin [one device; separate pilot server entry]
     │          initial G2-1A: passive observe-only (no mutations)
     │          later G2-1B only if actual NextUp path is proven
     ▼
[preview-only ingress, proposed 127.0.0.1:17431]
     ├── Everything, observe mode ───────────> Existing AIO 127.0.0.1:3240
     └── exact GET /jellyfin/Shows/NextUp only,
         after explicit intercept opt-in ─────> v1.4 Gateway 127.0.0.1:17432
                                                  └── GET same-user AIO
```

Do not point a full Odin Jellyfin server entry **directly at the Gateway**, because the integrated Gateway deliberately only serves NextUp/opted-in Resume, not complete auth/library/playback APIs.

## G2 acceptance and rollback

**Before any live pilot:** select Odin device (Mac / iPhone / iPad / Apple TV), confirm Odin supports adding a **separate** second server entry without replacing its active AIO production one, and review the exact preview scheme/ports/security. Publish nothing.

**G2-1A PASS** requires Odin's own requests actually observed through a separately approved preview with anonymous counters only; categorization may be `ODIN_NEXTUP_ROUTE_OBSERVED` or `ODIN_RESUME_ROUTE_ONLY`. If it does not issue NextUp, **G2 cannot be called Gateway NextUp PASS** regardless of 200 response or populated shelf.

**G2-1B PASS** additionally needs same-user authenticated Odin NextUp response through the Gateway, matching request counts on preview ingress and Gateway, stable shelves without lost Resume/metadata, and zero history/playback writes during passive discovery. The real alias pair remains absent from known sample, so the only 2→1 proof remains G1B synthetic; don't manufacture duplicate watched state.

**Rollback**: stop using the pilot server entry; shut down/remove **only** preview-only ingress & temporary Gateway resources after confirming exact identity. Verify current AIO normal URL and RC6 image remain healthy, along with unaffected live client sessions. Do not restart nginx/AIO/Bridge broadly or delete any production stack.
