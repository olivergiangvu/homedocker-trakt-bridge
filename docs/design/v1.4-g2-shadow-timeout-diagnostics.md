# G2-1B — Shadow-only HTTP timeout diagnostics (source + mock tests)

## Evidence from the operator, not inferred

Real Odin macOS pilot on the HomeDocker host using Draft PR #131 commit `0dcfa242404519a1b30ed94d6621cf4d0e68169e` produced:

- Ingress: **4 NextUp, 4 Resume**, 13 AIO 2xx, zero client AIO 4xx/5xx in that 3-minute trial; the local SSH tunnel **worked**.
- Shadow: **3 attempted**, **0 completed**, **3 timed out**. Actual v1.4 Gateway observed **3 NextUp requests**, **2 upstream transport failures**, and exactly **3 allowlisted upstream AIO GETs**.
- Verified legacy source: **17 shows / one alias group**, no production SQLite or playback writes, no Gateway response served to Odin, original AIO responses preserved.
- AIO `/System/Info/Public` directly from the same HomeDocker host returned HTTP **200** with curl in approximately **5 ms** and native Node 24 `fetch` in approximately **218 ms**. **This proves only public-health reachability** and does not qualify the authenticated NextUp API or explain its transport failures.

**Conclusion:** G2-1B real-client shadow **is not PASS**. The old ingress used an independent **5-second** shadow timeout but real Gateway could spend **up to 15 seconds on its initial AIO NextUp upstream fetch**, plus up to 8 seconds for each additional user/metadata API batch. Three shadow timeouts were therefore a non-diagnostic mismatch. Two Gateway upstream transport failures are a separate observation; neither is proven to be caused by Node networking vs AIO response delay, aborts or overloaded metadata. Zero live alias removals cannot prove absence of duplicates because no full shadow response completed.

## Proposed diagnostic refinement, still **Draft/unmerged**

1. The real **Odin-to-AIO passthrough stays unchanged**: original AIO response to the Odin pilot; no Gateway return payload ever reaches Odin.
2. Shadow is still **GET NextUp only**, maximum three attempts and one outstanding, in the same trusted loopback Gateway process. Increase only its independent upper deadline from **5 seconds to 25 seconds** (absolute, not sliding idle timeout); enforce maximum 30 seconds in factory config. The separate Gateway initial NextUp upstream fetch remains 15 seconds. Any shadow timeout fails only the shadow (never Odin playback or response).
3. Add **anonymous scalar counters** by allowlisted Gateway AIO GET stage: `aio_nextup_*`, `aio_users_me_*`, and `aio_metadata_*`. For each stage record attempts, HTTP 2xx where appropriate, transport failures, and aborts for NextUp; no ID, path, raw URL, query, token, timing per media or exception strings. Include existing Gateway upstream response max milliseconds and completed response count in the **strictly whitelisted** final report.
4. Node 24+ via user-owned `nvm`; only execute after privilege drop; RC6 DB read-only; same pinned RC6 digest/one profile and 17 shows/one alias group. Only one short-lived ingress 17431 and Gateway 17432; no new Docker container, nginx change, Trakt API call or schema migration.
5. Prior to another real pilot, require CI PASS and operator approval. Reuse the existing Odin **AIO G2 Pilot** entry and SSH tunnel only. Browse Home/Continue Watching; no Play, Mark Watched, or Trakt sync. Ctrl+C cleanup, max 3 minutes.

## How to interpret the next report

- `shadow_completed>=1` and `shadow_2xx>=1` with `gateway_nextup_responses_completed>=1`: G2-1B candidate has evidence of an actual finished Odin-origin Gateway GET, but still needs correct same-user/profile mapping, no write checks, source stability and operator review. **Not automatically G2-1C approved**.
- `aio_nextup_attempted>0`, `aio_nextup_http_2xx=0`, `aio_nextup_transport_error>0`: failure is earlier, on the actual authenticated Gateway→AIO NextUp fetch. Public health success does not resolve it.
- `aio_nextup_http_2xx>0`, `aio_users_me_attempted=0`: Gateway got a NextUp HTTP response but did not enter identity normalization (may depend on response body/shape/filtering guard; not proof of a fault).
- `aio_users_me_attempted>0` with failed responses: investigate account verification/metadata **without displaying identifying values**; do not bypass same-user safety.
- `aio_metadata_attempted>0`: metadata stage reached. `gateway_fail_open_normalization>0` means unchanged NextUp was intentionally preserved rather than hiding media.
- `shadow_timeouts>0` with completed count 0, even at 25 seconds: stop. Do not arbitrarily increase beyond this bounded pilot; use timing and staged counters for an isolated next investigation.

All metrics are aggregate and exist only in Node RAM until its final sanitized report. These changes do not claim to fix AIO metadata 5xx observed in earlier G2-1A trials or other unexplained 4xx.
