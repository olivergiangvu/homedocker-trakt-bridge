## Minimal next source/CI-only change, *not deployed*

The same unprivileged opt-in observer adds two static, anonymous classifications to its temporary nginx access-log tokens:

1. `odin_items_subroute` from a `map $uri`, **fixed** values: `item_detail` (`/jellyfin/Items/{opaque_id}`), `item_subresource` (some child path), `items_collection` (exact root), `libraries`, `items_other`, `not_items`. It never records any actual item ID, URL, request query, metadata or account.
2. `odin_upstream_headers` from `map $upstream_header_time`, **fixed** values `received` if a numeric time indicates nginx observed upstream response headers, or `missing` otherwise. No header-time values or upstream address are ever logged. `received` is evidence of an upstream HTTP response; `missing` is ambiguous (may be upstream connection problem/timeout or proxy-generated error). **This is not an absolute root-cause determination of AIO logic vs nginx transport.**

The raw temporary log line still has only bounded tokens: `<category> <http_status> <family> <static_subroute> <received|missing>`. It automatically disappears at Ctrl+C. Only these two **aggregate** report fields are added:
- `items_5xx_by_subroute`: counts in fixed categories.
- `items_5xx_upstream_response_headers`: `received` vs `missing` counts.

The observer still forwards GET/HEAD/OPTIONS and only optional AIO login POST to existing `127.0.0.1:3240`, always **without** Gateway interception; other writes remain locally blocked. No new host listener, Docker volume, nginx production configuration, public routing, application settings or Trakt history changed. Existing macOS SSH tunnel and separate **AIO G2 Pilot** server entry may be reused.
