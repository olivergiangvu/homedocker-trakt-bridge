# G2 — One-client NextUp route discovery and controlled pilot (Practical v1.4)

**State:** G1A/G1B/G1C technical tests PASS on HomeDocker. On 2026-10-17 the operator explicitly attested that the AIO configuration used for G1C belongs to the same person as the Trakt account connected to Bridge. This is **operator attestation**, not an independent cryptographic account-link proof. G2 remains OPEN until a real client request is observed traversing the Gateway.

**Do not interpret G2-0 preflight as a live client test.** `V140_STABLE_RELEASE_HOLD` stays in force. RC6, existing clients' normal AIO URL, nginx routing, Trakt writer, production SQLite and AIO database remain untouched.

## 1. Client selection and known upstream constraints

Provisional first pilot: **AIOStreams Desktop on the operator's Mac**. Upstream AIO docs explicitly describe a standalone native window over the same web client, capable of adding/changing server independently via its account menu:
- [AIOStreams Desktop technical README](https://github.com/Viren070/AIOStreams/blob/main/packages/desktop/README.md)
- [AIOStreams Desktop guide](https://docs.aiostreams.viren070.me/guides/desktop-app/)
- [Jellyfin app server address convention](https://docs.aiostreams.viren070.me/apps/jellyfin/)

**Not yet established:** whether this particular client/version/selected account actually issues `GET /Shows/NextUp`, whether the server path has `/jellyfin` prefix, which additional auth/picker endpoints are required, or whether its macOS WebView accepts an SSH-tunneled HTTP localhost preview. These must be observed in the client pilot, not assumed from a feature label.

The one-process v1.4 **Gateway module is not a complete Jellyfin server**: it only accepts exact `GET /Shows/NextUp` and, if separately enabled, Resume raw passthrough. Directly replacing an existing client's AIO server address with a bare Gateway address would break login, libraries, images, playback and other API routes.

## 2. Minimal preview-only ingress plan, not installed yet

Proposed host loopback candidate ports **17431** (preview nginx listener) and **17432** (temporary Gateway listener). These are merely suggestions, neither port is reserved. G2-0 preflight scans Linux `/proc/net/tcp` and `/proc/net/tcp6` and STOPs on any current listener conflict.

A subsequent *separately reviewed, explicit opt-in* candidate will use an **entirely separate** nginx loopback-only server/address — **never mutate the current production AIO vhost** — and dispatch according to the following intended matrix:

| Request arriving at preview-only server | Destination |
|---|---|
| Exact `GET /jellyfin/Shows/NextUp` with unmodified query | Temporary Gateway's `/Shows/NextUp` |
| All other Jellyfin GETs (including `/Users/Me`, `/Items/*`, `/UserItems/Resume`) | Direct to existing AIO `127.0.0.1:3240` |
| Authentication and playback `POST`s, other non-GETs | Direct to existing AIO, not to Gateway; **do not press Play during initial read-only client discovery** |
| Any non-Jellyfin path | Excluded from preview or explicitly reviewed AIO passthrough — cannot fall accidentally into Gateway |

Exact Host, authentication headers, Set-Cookie, websockets, query handling, base-prefix, CORS and additional AIO app paths must be validated against *actual* traffic **before** installing preview nginx routing. Client NextUp coverage is only claimed after verified same-user NextUp requests reach Gateway and aggregate `nextUpRequests` rises; playback/other route integrity must remain unaffected.

Mac-side candidate access would be a dedicated SSH `-L` tunnel to the loopback preview, or another separately authorized isolated HTTPS preview if the app declines HTTP localhost. No DNS/DDNS changes, public port forwarding or existing nginx vhost edits are authorized now. The current user's production server entry must be preserved; add a separate **pilot server entry** only after end-to-end connectivity and secret-free logging are reviewed.

### Zero-raw-identity telemetry

The ingress plan must never log full URLs, tokens, session headers, item IDs, media titles, usernames or raw NextUp bodies. Only anonymous counters are allowed: pilot requests, matched path count, forwarded NextUp count, upstream errors, Gateway unchanged/removed counts and latency. **HTTP 200 is not proof of route interception**; the matched-route counter + Gateway `nextUpRequests` and the client GUI must agree.

### Stop / rollback

- If app traffic does not request NextUp, classify `G2_CLIENT_ROUTE_NOT_OBSERVED`, not PASS.
- If client needs extra paths, the preview must forward them to AIO, not silently send them to Gateway.
- If any non-GET/personalized request goes to Gateway unexpectedly, stop the pilot.
- Any unexpected timeline/Continue Watching mutation, Trakt discrepancy, 401/403 loop, CORS problem, client media failure or AIO health degradation triggers stop.
- Rollback is independent: revert **only pilot server address to original AIO**, remove any authorized preview-only nginx config/listener and temporary candidate; check RC6 image digest/AIO/latest and stable endpoint. Do not restart or delete unrelated services.

## 3. G2-0 host inspection now available — zero changes

It creates no listening sockets, services, passwords, client sessions, nginx files, containers, routes, DNS or Trakt changes.

- `nginx_preview_configuration_installed=false`

- `client_nextup_request_path_observed=false`

A GREEN preflight means **readiness to plan**, not license to install anything. Port availability is a point-in-time observation, not a reservation. The G2 acceptance report must retain the difference between **client path observation** and **positive alias suppression** (the latter currently synthetic-only; no production duplicate may be fabricated).
