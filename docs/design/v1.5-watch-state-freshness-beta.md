# v1.5 beta — AIOStreams watch-state freshness (HomeDocker-owned)

**Status:** beta branch; production v1.4 stays unchanged. No deployment or release promotion implied.

## Single target

When Trakt has a new completed episode, AIOStreams Web/Desktop eventually displays the updated watched state **without a manual page reload**, preserving canonical Trakt authority.

Observed HomeDocker 2026-10-21:
- AIOStreams `latest` imports one watched row from Bridge (`origin=import`, `played=1`) at 23:48:08 ICT.
- Bridge `pull ok` at 23:48:15 reported watchedEpisodes=8427, watchedChanged=true.
- AIO background pull is ~1800s; Bridge cache TTL/hint both 60s.
- AIOMetadata user `Your trackers=off` and `Watch tracking=true`; no change.
- Import-to-WebSocket notification is absent on the examined AIO pull path; this is source review, not yet an end-to-end client regression proof.

## Beta discipline — smallest safe change

1. **AIO only through supported configuration.** For a separate controlled canary use `WATCH_STATE_PULL_INTERVAL=300` (seconds) while leaving `WATCH_STATE_PULL_TTL=300` initially; restart AIO via its existing Compose owner after backing up and recording image IDs. Do not bake AIO config into Bridge or silently restart upstream. Default production cadence remains unchanged until operator opts in. Measure authenticated Trakt GET, 429, stale/error and playback regressions before 60s experiments.
2. **HomeDocker-owned change detector.** `src/watch-state-import-witness.mjs` reads the existing AIO SQLite **read-only** and scopes to the one exact active Bridge sink, same uuid/persona. No timer, runtime switch, SQLite writes, network, or Trakt I/O is installed by this commit. It reports aggregates only, intentionally no titles/IDs/credentials.
3. **Notification relay only after acceptance.** If a real before/after client test proves automatic invalidation missing, implement an opt-in, exact-route, authenticated WebSocket passthrough **within the existing Bridge/Gateway process**, preserving the AIO upstream WS handshake, keepalive, remote commands, close semantics and all non-watch messages. Emit Jellyfin `UserDataChanged` only for a proven imported change and that user's verified socket. Never route the whole Jellyfin API, intercept native Trakt, or create a second Bridge/DB/writer. No new public listener.
4. **Do not modify successful v1.4 code paths.** No edits to `trakt.mjs`, `managed-trakt.mjs`, scrobble, dedupe, anti-echo, reconciler, profile, gateway NextUp filtering, canonical IDs, nor the identity graph. No `dropped` actions. No AIO source fork/patch or direct watch-state DB mutations.

## Stable acceptance gates

- **Import correctness**: new watched episode appears as `origin=import` from exact Trakt sink; no AIOMetadata competing read authority.
- **Refresh**: with AIO Web and Desktop continuously open and no interaction, state updates after confirmed AIO import; capture wall times for Trakt history, Bridge poll, AIO import, WS notification, UI observed.
- **Latency**: report measured p50/p95 on repeated events, not a guaranteed 15s claim. With 300s polling, <15s end-to-end cannot be promised.
- **Safety**: login/WS upgrade enforced upstream; no cross-user/persona signals; WS reconnect and playback pass-through remain unchanged; no extra Trakt POST, no synthetic played/unplayed, no history duplicate.
- **Operational**: 24h observation with no rate-limit amplification and no surprise resets; canary flag default off; instant revert nginx exact WS location and AIO supported config; v1.4 image rollback remains available.
- **Tests**: unit tests for witness and socket framing/auth/scope on the actual relay, plus real Web/Desktop canary. Passing witness tests alone does NOT mean UI fix delivered.

## Explicitly deferred

No adaptive activity-probe architecture until the 300s canary shows it is needed; no polling of 8k watched episodes every 15s; no extra gateway listener/DB; no CrossWatch rewrite; no AIOMetadata config changes; no OTA NextUp redesign.

## Deployment state

Current beta **only contains the read-only witness and tests**. The socket relay and production config canary are **not implemented or deployed yet**. This is the safe cut between investigation and behavioral change; do not label it v1.5 stable until the gates above pass.
