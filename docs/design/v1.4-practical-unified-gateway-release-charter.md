# v1.4.0 — Practical Unified Gateway: release charter and Definition of Done

**Decision:** 2026-10-16; explicitly approved by the HomeDocker operator after a full project review.
**Scope:** Practical Unified Gateway, not a privileged-Docker/root-resistant infrastructure security product.
**Release state:** `V140_STABLE_RELEASE_HOLD` until the gates below have *observed* acceptance evidence and the separate release workflow policy change is reviewed.
**Relationship to history:** Supersedes the **scope/prioritization** of the research-centric R23D workstream; it does **not** erase its test evidence, waive the core application security requirements, undo real cleanup, or turn a Draft PR into a stable artifact.

## 1. Product goal and observable end-user outcome

Deliver **ONE HomeDocker Trakt Bridge v1.4.0 product and dashboard**. Trakt remains the single canonical watch/history authority. The Bridge retains its existing sync engine and adds a Bridge-owned, opt-in Jellyfin-compatible **NextUp Identity Gateway** based on a profile-scoped verified canonical IMDb/alias graph.

The practical user-facing outcome is: when one authenticated AIO Jellyfin user's `GET /Shows/NextUp` contains two *safely provable* spellings of the same show (a known Trakt canonical series IMDb and its verified alternate IMDb), the gateway returns the one appropriate card **only if** a non-competing resume decision is supported. Uncertainty, two active resumes, incorrect user mapping, stale/missing graph, missing metadata, and unqualified pagination fail open to the unmodified AIO response.

This is a **read-only API-view projection**. It does NOT merge underlying AIO watch-state records, rewrite AIO SQLite, rewrite Trakt history, fabricate item IDs, automatically drop series, or normalize Resume.

## 2. Scope for this release

### Required / in-scope

1. Integrated app: existing Trakt Bridge sync engine, an optional gateway listener/module, **one existing Bridge dashboard** showing truthful listener, identity graph and aggregate metrics. No second permanent Trakt writer, identity DB or dashboard.
2. Identity: same-user `/Users/Me` authorization; explicit `AIO User ID → connected Bridge profile → verified alias graph`; bounded authenticated `SeriesId → series ProviderIds.Imdb` lookups; conflict quarantine; no guesses from titles, opaque IDs or episode ProviderIds.
3. Jellyfin surface: normalize **only** qualified `GET /Shows/NextUp`; preserve ID, `UserData`, pagination and unknown fields for retained items. `/UserItems/Resume` and legacy Resume remain OFF unless separately tested as *byte-for-byte passthrough*; playback, streaming, catalog, WebSockets, authentication and all other routes remain AIO-owned.
4. Single writer: native Trakt wins; existing Bridge watch/scrobble semantics and RC7 safeguards unchanged; no second history writer or hidden fan-out; no direct AIO DB edits.
5. Security/operations: default OFF; exact-scope AIO user checks; client credentials never exposed in logs/argv/URLs; bounded body, concurrency, timeout and cache; no privileged mode, Docker socket, host network, arbitrary upstream proxy, broad mount or host-wide firewall override; health and clean disable/rollback.
6. Actual clients: prove real **supported** AIO/Jellyfin client route and one account end-to-end; other clients are marked explicitly supported/unsupported based on their real API path.
7. Release engineering: reviewed consolidated candidate based on current `main`; immutable image digest, online SQLite + Compose/env backup and verified rollback; restart/AIO rolling compatibility, resource and functional regression, scoped nginx path, human approval before rollout.

### Explicitly deferred / not a stable release blocker

- Resume normalization; general multi-provider metadata reconciliation; AIO internal watch-state cleanup/rewrite/auto-drop.
- CrossWatch backfill, additional writers, broad partner tracker fan-out or automatic secondary-to-primary role changes.
- Guaranteeing coverage for clients not using the route (Odin/AIO Desktop, Remux, Trellis, Strand, etc. require *observed* classification).
- Hardening against **malicious Linux root or unrestricted Docker Engine API administrators on the same machine**. Such privileges are **trusted operator capabilities** in this HomeDocker threat model. Independent VM/firewall enforcement is a different future product tier.
- Further R23D nft/tc/kernel-lease/systemd-guardian/QEMU experimental milestones that do not directly unblock the approved functional pilot. Preserve the archival evidence and known negative tests as references; **do not run them on HomeDocker as release prerequisites**.

### Security boundary retained

**Trusted:** host root, Docker administrators/Portainer operators with Engine API access, the Engine itself and the operating system. **Untrusted:** Internet/LAN clients, Jellyfin-compatible clients, addons, external media providers, API request bodies and metadata. Practical release does not excuse SSRF, cross-user data leaks, unauthorized access, WAN-exposed internal listeners or credential logging. Docker-root bypass from the R23D B1S experiment remains a documented fact, not a claimed mitigation. No untrusted process gets Docker Engine privileges. Use existing host nginx to expose only reviewed exact routes when *explicitly opted in*; do not broad-reroute /jellyfin.

- [ ] CI passes on consolidated source with gateway disabled by default, exact image metadata and no behavior/schema drift for the existing sync engine.

**Exit:** agreed, source-frozen candidate with a minimized diff and validated current-host baseline; no host apply.

### G1 — Real identity and functional Gateway evidence

- [ ] Build isolated candidate using actual v1.4 app source and *only minimal, nonsecret and explicitly scoped* identity fixtures or a backed-up scrubbed snapshot. Verify the one connected profile relationship without exposing Trakt OAuth or AIO credentials to test artifacts.
- [ ] Confirm authenticated same-AIO-user `/Users/Me`, matching exact Bridge profile and active verified graph (revision and aliases), and series metadata matches. Prove mismatched AIO user gives **no normalization**.
- [ ] Prove **actual filtering effect** on a qualified dual-IMDb NextUp fixture (`before 2 distinct alias cards → after 1` when unique safe winner) **and** that competing active resumes, pagination ambiguity and unverified cases remain unchanged. If current real AIO NextUp has no pair, do NOT create/write fake viewing history to manufacture one; use an isolated fixture plus separately show actual live metadata/user mapping.
- [ ] Compare AIO and Gateway responses for identical authenticated session, strict preservation of all remaining item IDs, `UserData`, opaque fields and canonical history read state. A subset PASS without an observed effective filtering case is insufficient.

**Exit:** same-user functional normalization proved on a real authenticated source path *plus* an isolated positive duplicate fixture, zero production history writes.

### G2 — One real-client opt-in pilot

- [ ] Determine which request path Odin/AIO Desktop or the chosen supported Jellyfin client *actually calls*. Choose one known supported client; do not assume every client follows `/Shows/NextUp`.
- [ ] Route only the allowed NextUp path through the candidate, on localhost/native nginx opt-in test ingress. All catalog/playback/stream/WebSockets, auth and Resume go directly to AIO, or Resume stays byte-identical if separately approved.
- [ ] Observe true request arrival and effective client UI/API behavior; explicit opt-out rollback takes effect without changing AIO latest or Bridge history.
- [ ] No regressions in real scrobble/watched/unwatched, no duplicate Trakt write ownership; distinguish any client-native Trakt state from Gateway output.

**Exit:** one end-to-end real-client success without route sprawl or history damage.

### G3 — RC hardening, backup and rollback

- [ ] Review one `1.4.0-rc.1` integrated Docker image and immutable digest; Gateway default OFF. CI tests for same user, other user, zero/one/two resumes, malformed/large response, timeouts, fallback, metadata concurrency, dashboard authorization and disabled-state health.
- [ ] Independently verified SQLite online backup **plus** Compose/env and current RC6 digest; isolate protected backup from candidate; perform an **actual restoration/rollback rehearsal**. No local DB rewrite or secret-bearing diagnostic export.
- [ ] Capture same-host baseline vs candidate latency (cold/warm p50/p95), idle and peak RAM, request/timeouts, 429/422 and duplicate NextUp; set pass/fail budget from baseline, not guesses. Validate restart + `AIOStreams:latest` compatibility.
- [ ] Run time-bounded pilot/soak and verify no new writer; operator reviews acceptance matrix and rollback evidence.

**Exit:** qualified RC with clear resource budget, protected restore and practical rollback.

### G4 — Stable publish then host deployment

- [ ] Human-reviewed decision to lift/replace v1.4 tag release-workflow HOLD **only after G0–G3**. Keep current v1.3.0 tag/image immutable and never retroactively mutate `:latest`.
- [ ] Bump package/config version to 1.4.0, CHANGELOG/release notes/Docs; freeze source SHA; CI build + publish exact digest, signed/checksummed release metadata as configured.
- [ ] Deploy **Bridge-only** via reviewed Compose operation; AIOStreams, other stacks, nginx shared routes untouched except the separately approved exact NextUp route; validate rollback and post-deploy health, identity, user/session/route, Trakt event pulse.

**Exit:** *publishing* and *installing on HomeDocker* individually confirmed; any new live blockers reinstate HOLD.

## 5. Stop-the-line rules

The following remain **NO-GO** without separate approval:
- Changing production Bridge SQLite, importing identity graph to production or reading/copying OAuth secrets to a disposable canary.
- Docker/Portainer mass-redeploy, AIOStreams image pin/fork/restart, changing other clients, changing public nginx routes without a backed-up exact-route rollback.
- Creating/updating a stable `v1.4.0` tag while the existing release guard is present or before explicit review; bypassing the guard from an older commit is not release qualification.
- Treating R23A retirement as a reason to disable Docker/backup provenance checks.
- Requiring the retired R23A to be recreated or resurrecting R23D firewall/security experiments solely to turn an obsolete preflight green.
