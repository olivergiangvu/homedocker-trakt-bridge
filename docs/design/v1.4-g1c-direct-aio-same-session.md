# G1C — Direct same-session Gateway→real AIO read-only acceptance

**Status:** Draft implementation; no HomeDocker changes; `V140_STABLE_RELEASE_HOLD`.

After G1B operator PASS on 2026-10-17 (20 real AIO NextUp rows preserved, 17 verified legacy shows / 1 alias group imported into *RAM*, synthetic 2→1), G1C deliberately tests the **one missing technical link**: an actual v1.4 Gateway HTTP process issuing authenticated `GET` directly to AIO's Jellyfin endpoint with the exact user's existing AIO session.

## Scope

- Pinned main-based practical integration (G0 #119 → G1A #120 → G1B #121 → G1C).
- Host script `scripts/audit-v140-g1c-direct-aio.py` reuses proven G1A/G1B read-only Bridge identity scan, confirms pinned RC6 Bridge image, unchanged AIO image and `127.0.0.1:3240` mapping, confirms temporary container name unused, then GETs AIO public health. **No credentials or containers in default preflight.**
- Interactive authorized mode: hidden **existing AIO token** for GET-only, or **one AIO login POST** with hidden config credentials. Host verifies AIO `/Users/Me`.
- Exactly one ephemeral, read-only, unprivileged RC6-Node Docker container using `--network container:aiostreams`, read-only Git checkout and **no production data mount, Docker socket, published port, persistent storage, Trakt token or AIO config/password**. Inside AIO's existing netns, runner `scripts/probe-v140-g1c-direct-aio.mjs` calls `http://127.0.0.1:3000/jellyfin` and creates the v1.4 Gateway listening on a **random free 127.0.0.1 port in the same namespace**, then closes it.
- Gate creates only **ONE RAM Identity Graph** from the same connected Bridge profile's RC6 scrobble-derived cache. Real token **necessarily enters temporary Node RAM through bounded stdin** for a genuine same-session request. It must not enter command args, env, files, logs or release artifacts.
- AIO source GET NextUp → authenticated Gateway GET NextUp → AIO source GET NextUp, with strict complete JSON comparison. On no alias twin, all records, `UserData`, counts and opaque fields must remain untouched. The Gateway independently requests AIO `/Users/Me` and bounded `/Items/{SeriesId}` using that same token. Any changed source, wrong account, HTTP timeout, metadata fail-open, or unexpected filtering is **STOP**, never a misleading PASS.
- Node HTTP egress restricted *in application code* to exact AIO origin and `GET /Shows/NextUp?Limit=20`, `GET /Users/Me`, `GET /Items/{SeriesId}`, with redirects disallowed. **Not kernel-level network egress confinement**: an ephemeral process sharing AIO's netns can technically reach other destinations on that namespace. This trade-off is reviewed against the Practical Gateway trusted Docker/root-administrator threat model and avoids new host-wide firewall, relay or systemd complexity.

### What this does **not** prove

AIO's user ID and Bridge's connected profile ID are two distinct account systems. Supplying a matching *configured pair* and proving AIO accepted the token verifies **technical binding and fail-open enforcement**, but it is NOT an independent proof the AIO account is actually owned by the correct Trakt profile. Operator ownership review or another independent source is still required before G1 signoff. The candidate is not routed from a real client, and it does not publish a production Gateway. **G1/G2 remain OPEN until owner signoff and one real client opt-in**.

No AIO database/content writes, no history/playback/scrobble writes, no real Trakt HTTP calls, no RC6 changes, no nginx/Portainer changes, no Graph migration persisted to production, no second writer, no version/tag/release unlock.
