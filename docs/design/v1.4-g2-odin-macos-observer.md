# G2-1A — Odin on macOS, directly using AIOStreams (no Jellyfin intermediary)

**Scope corrected from operator statement (2026-10-17):** native Odin on macOS is already configured **directly** against AIOStreams' own Jellyfin-compatible API. Do not introduce Jellyfin server or Remux or reconfigure its existing AIO server. The user explicitly selected Odin and asked not to change HomeDocker production.

**Research sources:** [Official AIO Jellyfin Connect](https://docs.aiostreams.viren070.me/apps/jellyfin/) states a **plain server address ending in `/jellyfin`** accepts a config UUID/alias and its password/PIN; a sign-in-picker link may instead include credentials in the URL and **must never be pasted into logs, chat, CLI, CI or proxy config**. [Odin official site](https://odinapp.dev/) and [privacy policy](https://odinapp.dev/privacy.html) describe native Mac support, an internal Continue Watching cache, server watch-state writes and optional separate Trakt credentials. It is **NOT known** whether this Odin build calls NextUp, Resume, UserData, or local cache, and a populated Continue Watching shelf alone cannot prove a NextUp request.

Existing **G1C** has already demonstrated direct authenticated Gateway→AIO read-only NextUp GET, matching AIO user and 20 metadata requests; **G1B** synthetic positive alias 2→1; G2-0 host preflight confirmed RC6 unchanged and potential preview ports 17431/17432 free at a point in time. **G2 remains OPEN** pending Odin traffic evidence.

```text
Odin on Mac (NEW TEST SERVER ENTRY ONLY)

       │

       │

         NO Gateway on this path yet
```

**Run observer only with separate operator approval.** `scripts/audit-v140-g2-odin-macos-observer.py` provides:
- `--mode preflight`: reuse existing G2-0 Docker/SQLite read-only baseline and inspect nginx executable. No listener, credentials, client, nginx config or production writes. Requires `sudo` for RC6 SQLite inventory.
- `--mode observe --confirm V140_ODIN_MACOS_EPHEMERAL_OBSERVE_ONLY`: explicitly launched **as a normal unprivileged Linux user (never sudo)**. Verifies current loopback port 17431 not occupied and AIO public health; starts `nginx -c <new, private temp nginx.conf> -g 'daemon off; master_process off;'`, separate from existing host nginx. It does NOT edit `/etc/nginx`, signal/reload production nginx, persist a systemd unit, create Docker container, publish LAN/WAN port, modify upstream AIO URL or touch Trakt/Bridge DB. Listener bound to `127.0.0.1:17431` only. AIO path/headers/query proxied unchanged.
- Access log writes **only** one `category HTTP_status` pair per request into a private `tempfile.TemporaryDirectory` with automatic cleanup (no URLs, queries, IPs, user IDs, headers, cookies, titles, IMDb IDs or request body). Nginx error logs are suppressed; the only terminal report is aggregate counts for NextUp, Resume, UserData, Auth, Other and 2xx/3xx/4xx/5xx. Temporary log is destroyed on Ctrl+C.
- All `GET`, `HEAD`, `OPTIONS` go to existing AIO, **including NextUp**. Only `POST /jellyfin/Users/AuthenticateByName` is allowed to create a session for a *separate* Odin pilot server entry; any other method (including watched/history/playback POST) is denied locally 405. This intentionally may limit app functions during observation. **Do not press Play, mark watched, manually sync or enable optional Odin→Trakt sync.**
- All requests transit only the operator's authenticated SSH tunnel plus host loopback; do not use public DNS or change nginx production vhosts. The Mac-side 17431 port must also be available, separately from the host port inventory.

### Pilot review flow (not performed yet)

1. Operator confirms **Odin Mac can add a second, separately named server entry** without deleting, replacing, signing out or resetting the current AIO server. The public Odin docs do not clearly guarantee this UI capability. If a second entry is impossible, **STOP**; do not replace the active server or alter its local watch cache.
2. With G2-1A preflight PASS, operator separately authorizes the unprivileged observer. In one HomeDocker SSH terminal run observe and leave running. In a **different Mac Terminal** create a local forward using the *existing working SSH host*, e.g. `ssh -N -L 17431:127.0.0.1:17431 <existing-home-server-host-alias>`. Actual SSH host/port must be supplied by operator; never expose credentials.
3. In Odin **new pilot server only**, use **plain** `http://127.0.0.1:17431/jellyfin`, AIO config UUID/alias + password entered **inside Odin UI only**; **do not use a sign-in-picker URL**, whose path may embed credentials. No tokens go into logs/terminal/GitHub. If Odin refuses localhost HTTP due to TLS/ATS or cannot hold a second server entry, classify `PILOT_CLIENT_CANNOT_CONNECT`; no bypass of security or production vhost change.
4. Without playing or marking anything, navigate Home and Continue Watching, optionally refresh library view. Then `Ctrl+C` in observer terminal, wait for `ODIN_OBSERVER_FINISHED_NO_GATEWAY_INTERCEPT`, and share only its anonymous JSON counters. No raw URLs.
5. The counter `observed_nextup > 0` demonstrates that **some client through the preview** requested exact prefixed `GET /jellyfin/Shows/NextUp` during the isolated session (provided the pilot URL was only used in Odin, not other tools). If `observed_resume > 0` and `observed_nextup=0`, Odin's Continue Watching may be Resume-based. If both zero, app may use UserData or local cache; do not assert any Gateway behavior.
6. **G2-1B is NOT AUTHORIZED**: only after a real NextUp route is observed do we design temporary Gateway plus selective interception, with an opt-in test and per-client rollback. The unprivileged observer's output must always report `gateway_forwarded_requests=0`, `real_gateway_client_qualified=false`.

To roll back the client pilot, stop the SSH tunnel and remove **only the Odin test server entry** (after checking the active AIO entry was unaffected). Existing production AIO server, RC6 Bridge, nginx config, library, other clients, credentials and all Trakt history remain intact.
